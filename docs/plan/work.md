
# 施工派单与工单池（WORK）

## 0 这份文件是什么

- **是**：分析侧（评审 / 测试 / 读码）把**已拍板的规格**翻译成**可执行的施工单**，交给开发侧（CodeBuddy）照做。每条单都点名：**改哪个文件的哪几行、怎么做、不许做什么、怎么算做完**。
- **不是**：不是规格真源。规格在 `art/art.md`、`setting/WORLD.md` 等处；这里的做法**必须能回溯到一条规格**，回溯不上的不许开工。
- **一文件两个区**：**§0–§5 是派单**（登**动作**：怎么修、按什么顺序修），**§6 是工单池**（登**问题**：哪里坏了，含源码行号与证据）。一条问题可拆成几条动作；一条动作可能同时关掉两条问题。**做完一条，§6 对应条目才允许删。**

## 0.2 硬红线（违反即回退，不接受解释）

1. **`Sim/` 零渲染依赖**——不许在 `Sim/` 里 include UObject / 渲染 / 输入头（[`../tech/tech.md`](../tech/tech.md) §2.2）。
2. **改表现层后 `bench` 的 digest 必须不变**。变了就是泄漏进 Sim，先修泄漏再谈画面。
3. **不新建模块**（`SolsticeSim` 已被实测否决）；新代码落主模块的子目录。
4. **不引入 Lumen / Nanite / 全 PBR / 体积云 / 体积雾**（`art.md` §2.4）。
5. **不出现纸质感**——纸纹、纸厚、纸纤维、撕裂边（`art.md` §0.5 红线 4）。
6. **不改 `docs/` 里的规格数字**。发现规格错了，写进 **§6 的 `A-nn`** 交用户裁决，**不许自行调整**。
7. `Build.cs` 依赖是白名单，只列真正被 include 的模块。
8. 新建 `.ps1` 必须 UTF-8 **带 BOM**；本地构建必须 `-NoUBA`（[`../ops/ENVIRONMENT.md`](../../tools/docs/ENVIRONMENT.md) §2.4.1）。
9. **一次只做一条单**。做完、验完、回写，再开下一条——不要五条一起改再一起调。
10. **相机只允许停在 32 个格点**（方位 8 × 俯仰 4）。不许新增任何能连续改 yaw / pitch 的入口——包括"顺手加个拖动""按住某键微调""自动环绕转快点"。这条口径见 [`../art/art.md`](../art/art.md) §2.6 与 `CHARTER` 第 59 轮；**加了就是回退**。

## 0.3 做完怎么回写（每条单必做四件）

1. **证据落盘**：截图放 `tmp/review/`，命名 `d0X_<用途>_<时间>.png`；grep / bench 输出贴进提交说明。
2. **关条**：在 **§6** 里把对应工单**整条删掉**（不是打勾）；若只关掉一部分，把剩下部分改写清楚再留着。
3. **记日志**：在 [`../CHANGELOG.md`](../CHANGELOG.md) 顶部加**一行**：`日期 | 做了什么 | 影响文件`。
4. **本文件**：把该单从「当前批次」移到「已完成」，只留 ID + 一句话 + 证据路径。

**R-29 尺寸只是分辨率：512² 不会比 128² 多出任何东西**（P0）
- 现象：把 `world.json` 的 `size` 从 128 改到 512，画面"变大"了，但山脉条数、河谷条数、生态域种类**一模一样**，只是边更细。文档里"大界 8+ 生态域含气候带"（`WORLD.md` §2.1）在实现上不成立。
- 因：`GenerateTerrain()` 把格号归一化成 `U = X / Size`（`SolsticeKernel.cpp:326-327`），所有噪声频率是常量（`TerrainNoise::*Freq`）——世界先被缩到 0..1 再采样，`size` 只改采样密度。另 `Radial` 只在 islands / basin / archipelago 用到（`:355` / `:378` / `:387`），ridges / canyon / plateau **完全不收边**，圆盘世界会出现断崖边。
- 改：① 频率改按**世界米数**：`U = X * TileSizeMeters / 100`（每 100 m 一个噪声周期），`V` 同理；② 形制参数入口化——`land_ratio` / `relief` / `ranges` / `bearing` 进 `GenerateTerrain`，地形改成「基础场 + 走向偏移 + 山脉带 + 侵蚀」的组合，`algo` 降级为"基础场类型"而不是整套算法；③ 径向项统一用 `Radial` 并**强制收边**（最外 3% 半径压到水位以下）；④ `MaxHeightMeters` 由 `relief` 缩放，不写死 64。
- **补充（2026-10-17 实机发现，同一病根）**：`Tuning::MaxHeightMeters = 64.0f` 是**写死的米数**（`Sim/SolsticeTypes.cpp:73`），而世界半径随档位变——128² 半径 64 m → **山高 = 1.0 R**（`WORLD.md` §1.1 判据 4 的上限是 0.55 R，**翻了一倍**，画面读成一个尖山包、没有平地）；512² 半径 256 m → **山高 = 0.25 R**（**低于 0.30 R 下限**，世界会平得没有山）。同一个常量在两个档位产出两种都不合格的形态。**改法**：`MaxHeightMeters` 由 `relief × R` 算出（`0.30–0.55 R`），不再写死 64；`relief` 目前**根本没被读**（`FWorldConfig.Relief` 无引用）。
- 验：同种子下 128² / 512² 的山脉条数按面积比增长（±1）；512² 至少出现 2 个气候带；四机位看边沿无断崖；**128² 与 512² 的最高峰 ÷ 世界半径都落在 0.30–0.55**；同 size 同种子的 bench digest 稳定。
- 源：`docs/setting/WORLD.md` §2.1（尺寸是尺度不是分辨率）/ §2.4 ① · `Sim/SolsticeKernel.cpp:326-327,343-390,355,378,387` · `Sim/SolsticeTypes.cpp:70-90`（Tuning）

- 因：两处叠加——
  1. `SolsticeRealm.cpp:455`：`const float Wet = Clamp(Rain*0.7 + Cloud*0.3, 0, 1); Fog->SetFogDensity(Lerp(0.008, 0.055, Wet));` —— **云量直接算进雾**。多云（云量 0.5）就已经 `Wet=0.15`、密度 ×1.6；而"多云"在 `WORLD.md` §3.2 的天气状态机里是「云量升高、降水 0」，**不该有雾**。雾在状态机里是独立状态（夜间 + 湿度 > 0.7 + 无风）。
  2. `SolsticeRealm.cpp:41/44/237-239`：`FogDensity=0.012`、`FogStartDistanceUU=2600`（= **26 m**），再按 `Scale = 6400/Radius` 缩放。128² 世界半径 64 m，**26 m 处就开始起雾**——也就是视野的一半之后全在雾里；这个常量是按"半径 64 m 的世界"定的，但 `6400` 是 512² 的半径，两套口径混在同一个文件里。
- 改：① **把云从 `Wet` 里去掉**，雾密度只由「雾状态 + 降水」驱动；② 雾密度与起雾距离**按世界半径归一化**（`Start ≈ 0.35 R`，而不是写死 26 m），保证"远山有雾、近处清楚"在 128² 和 512² 上都成立；③ `art.md` §2.4 要求雾是**三层半透明平面**、不是指数雾体积——M0 可以先用指数雾过渡，但**上限要压住**（能见度不低于 0.6 R）。
- 验：晴 / 多云两态下，**画面不得有可见雾**；雾状态下 F1 机位仍能读出山脉轮廓与岸线；128² 与 512² 各截一张，远山模糊程度一致。
- 源：`docs/setting/WORLD.md` §3.2（天气状态机：雾的进入条件）· `docs/art/art.md` §2.4（雾 = 三层平面）· `World/SolsticeRealm.cpp:41,44,237-239,455` · 证据 `tmp/review/live_02.png` / `live_03.png`

### 相机与取景（R-36–R-37）· 2026-10-17 读码新增

**R-36 相机距离三套 clamp 互不相同，且远界写死 60000 把 512² 的全景锁死**（P0）
- 现象：`ASolsticeObserver` 里同一个 `Distance` 被三处不同的上下界夹：`Zoom()` = `[2500, 60000]`、`SetDistance()` = `[2500, 600000]`、`SetDefaults()` = `[2000, 600000]`。滚轮走 `Zoom()`，所以**滚轮的上限是 60000**。按 `FitDistance()` 算：`Fit = 1.09R ÷ tan(半垂直FOV) ≈ 5.63 R`，128² 世界（R = 6400 uu）Fit ≈ 36 000，勉强够用；**512² 世界（R = 25 600 uu）Fit ≈ 144 000 —— 滚轮从全景往近处滚一档就被砍到 60 000，全景再也回不来**（只有按 `F1` 走 `SetDefaults` 才能回到全景）。用户对这个的主观描述会是"放大以后没法退回去看整个世界的另一头"。
- 因：远界写成绝对 uu 常量（`SolsticeObserver.cpp:54`），而取景距离是世界半径的函数——**同一个数字在两个尺度下不可能都对**（与 `R-29` 的 `U = X/Size` 是同一类错误，只是一处在 Sim、一处在相机）。
- 改：① 相机自己不知道世界多大，所以**上下界由控制器每帧注入**（`SetDistanceRange(Min, Max)`），或让 Observer 持一个 `FitDistance` 缓存；② **远界 = 1.6 × Fit**、**近界 = 2500 uu 绝对值**（口径见 [`../art/art.md`](../art/art.md) §2.6；近界必须是绝对值，因为 1 格恒 1 m，"能看清一片苔"的距离不随世界变大）；③ 三处 clamp 收敛成一个 `ClampDistance()`，不许各写一套。
- 验：512² 世界滚轮推到最远仍能看到完整圆盘；按 `F1` 与手动滚到最远得到同一个距离（±2%）；`grep -n "60000\|2500\|2000.0f" SolsticeObserver.cpp` 只剩一处常量或全部消失。
- 源：[`../art/art.md`](../art/art.md) §2.6 · [`../CONSTANTS.md`](../CONSTANTS.md) §7 · `God/SolsticeObserver.cpp:37-62` · `God/SolsticePlayerController.cpp:33-42`
- ⚠️ **本条不改键位、不改手感**，只让距离的界正确。键位改动是 `D-10`（已定案，排在 `D-05` 之后）。

**R-37 摆件模式下相机完全失灵**（P1）

**R-38 世界读成"一只碗"：四周全是高壁、中心一片低地**（P0）

### 色彩失真（R-41–R-42）· 2026-10-17 读码追到根

> **这两条是"画面全灰白"的真凶，比换 Cel 材质更靠前。** 在此之前所有"改色板 / 改材质"的尝试都不会有效果——因为颜色在出屏前被压平了。**`D-02` 的验收依赖这两条先修好。**

**R-41 后处理没锁曝光，自动曝光把画面推到接近纯白，中间调为零**（P0）
- 现象：实测画面 `r2_01.png` 整体浅灰、对比极低。对世界区域做像素统计：**平均 RGB (207,204,201)**（三个通道差 6，等于无色）、**亮度中位数 0.910 / 最大值 0.953**、**平均饱和度 0.095**；亮度直方图是双峰——4235 个采样落在 `0.9–1.0`、2486 个落在 `0.6–0.7`，而 **`0.2–0.5` 整段是 0**。也就是"**大片接近白 + 一小片中灰 + 没有中间调**"。`art.md` §2.1 的 Cel 三段判据（亮 / 中 / 暗）在这里连**中间调都不存在**，谈分带没有意义。
- 因：`ASolsticeRealm` 的 `UPostProcessComponent` 只覆盖了饱和度 / 对比 / Gamma / Gain / 暗角 / Bloom / 颗粒 / DOF（`World/SolsticeRealm.cpp:111-145`），**一条曝光都没覆盖**。而场景光很暗（方向光 `SetIntensity(0.45)`、`SkyLight 0.20`，`:81,90,456`）。引擎默认 `Auto Exposure = Histogram` 会把这个暗场景往上推——**推过头就是现在这样：中位亮度 0.91，颜色被冲掉**（饱和度 0.095 就是这么来的）。这一条也解释了 `R-35`「雾一来自动糊白」的一半：不是雾变浓，是曝光跟着画面亮度漂。
- 改：① 覆盖 `AutoExposureMethod = Manual`（或 `Histogram` 但钉死 min/max 亮度）；② 给一个固定 EV，先在 `F1` 机位调到"草地饱和、天空不过曝"；③ 把曝光值当**风格参数**记进 `art.md` §2.4 的昼夜表，别写死在构造函数里。
- 验：跑 `python tools/checks/measure-frame.py <png> --box <世界区域>`，三项全 PASS——**当前基线：饱和度 0.095 / 亮度中位 0.910 / 高光占比 0.597，三项全 FAIL**；再补"静止 / 相机移动 / 起雾"三态平均亮度不漂（均值差 < 5%）。
- 源：[`../art/art.md`](../art/art.md) §2.1（Cel 三段）/ §2.4（昼夜四组参数）· `World/SolsticeRealm.cpp:81,90,111-145,456` · 证据 `tmp/review/r2_01.png`

**R-42 地形配色按"高度 ÷ 24 m"分档，而山高上限是 64 m → 全世界都落到"岩石"档**（P1）
