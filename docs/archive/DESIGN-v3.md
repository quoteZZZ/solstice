## 2. 体验支柱

1. **布阵就是决策**——每一格的摆放都在回答"谁先挨打、谁先出手"。位置是免费但最强的资源。
2. **合契的爽感**——三张同名卡合成升星，一次合契能把劣势翻成优势。这是本作的核心情绪爆点。
3. **天时改写棋局**——同一套构筑，在立春与霜降是两副模样。节气不是背景，是变量。
4. **一局一故事**——24 个节点、事件驱动的碎片化叙事；每一局的走向不同，逐局拼出全貌。
5. **败得体面，再来一次**——重开成本低（30–45 分钟一局），周目解锁持续给正反馈。

## 3. 世界观与叙事（原创，轻量、事件驱动）

> 完整设定见 [`STORY-v1.md`](STORY-v1.md)（同批作废）。此处只锁不可变骨架。

- **世界**：**四时界**。四季依**「岁轮」**轮转，万灵随节气生灭。
- **仪式**：每年**冬至**，四时界在**「岁盘」**上重演一次**「岁局」**，以定来年四季之序。主持者称**司岁者**。
- **你是**：新任司岁者，接手前任的**残局**。
- **危机**：**逆岁者**——认为岁局是牢笼，欲将岁盘**永远钉在至点**（时间不再流动 = 四季皆死）。
- **肉鸽的解释**：岁局可重演。败了即从**立春**重启，但**岁印**（记忆与经验）会留存。**"重开"是世界观内的机制，不是读档。**
- **叙事交付方式**：**碎片化、事件驱动**（非章节线性）。每个节点事件是一段短对话/一幕卡面级插画；真相靠多周目拼接。**绝不使用纯文字长块**。

**四条「节气主」**（每 6 层一位 Boss，即四域主宰）：庭主 / 海主 / 岭主 / 宫主。各有一位逆岁者的门徒镇守，终局面对逆岁者本人。

## 4. 核心循环

### 4.1 局内（一局 ≈ 30–45 分钟）

```
 立春起始：选值守者 + 初始卡组(12张)
        ↓
 ┌──────────────────────────────────────┐
 │  岁局地图（24 节点 = 24 节气）          │
 │  每节点三选一：遭遇 / 坊市 / 奇遇        │
 │        ↓                             │
 │  【遭遇】布阵期 → 交兵期 → 胜负          │
 │        ↓                             │
 │  结算：墨料 + 寿数(HP) 变化 + 掉落       │
 └──────────────────────────────────────┘
        ↓ 每 6 层：节气主（精英/Boss）
   第 24 节点：逆岁者 → 通关
        ↓
   败北 → 岁印结算 → 局外解锁 → 自岁首重演
```

- **寿数（HP）**：司岁者 30 点。交兵期落败按对手存活单位扣寿数。**寿数归零 = 本局结束。**
- **墨料（局内货币）**：战斗与事件产出；坊市购卡/刷新；**每 10 墨料产生 1 利息，利息上限 5**（自走棋式经济）。
- **岁印（局外货币）**：局末按进度结算，用于**局外解锁**（新值守者、新卡入池、起始加成）。

### 4.2 局外（元进程）

岁印 → **岁轮解锁树**：解锁值守者 / 扩充卡池 / 开启更高**周目难度（岁劫）**。**纯 PvE，进度可全解锁，无随机开箱。**

## 5. 战斗规则（回合制棋盘对战）★核心

### 5.1 岁盘（Board）

- **布阵区**：**2 排 × 6 列 = 12 格**（我方）。敌方镜像对称。
- **排的意义**：**前排**优先被近战攻击；**后排**受远程优先。**列**决定纵向攻击路径。
- **摆放规则**：卡只能落在空格；单位移动只在特定词条下发生（默认固定站位，强调"布阵一次性决策"）。

### 5.2 回合结构（双相回合）★原创

一个回合 = **布阵期** + **交兵期**。交替进行，直至一方寿数归零。

**① 布阵期（Deploy）——玩家手动**
- **墨**：每回合上限 +1（起始 1，上限 10）；**未用完不保留**（炉石式）。
- 可执行：打出**灵契卡**（部署到空格）、打出**术式卡**（即时效果）、使用**值守技**、**合契**（见 5.5）。
- 敌方布阵期由 AI 决策（规则式 + 预设脚本，**不含随机性主导**）。

**② 交兵期（Clash）——自动结算**
- 双方**全部存活单位**按 **SPD 降序**依次行动一次（同速按列序）。
- 每个单位：近战 → 攻击**同列最前排**的敌方单位；远程 → 攻击**最近的**敌方单位。
- 若某排已空，则攻击**相邻列**最近单位（避免空转）。
- 一方的场上有单位存活时，**直接攻击敌方司岁者**需满足「无阻挡」（无固守词条且前排已清）。

### 5.3 数值与伤害

```
伤害 = max(1, round( ATK × 相克系数 × 羁绊修正 × 天时修正 − DEF × 0.5 ))
```

- **相克系数**：五行环 **木克土 → 土克水 → 水克火 → 火克金 → 金克木** 取 **1.5**；被克 **0.75**；**日 ↔ 月 互克**取 1.5；**灵** 无相克恒 1.0。
- **羁绊修正**（§5.6）、**天时修正**（§6）为乘算，上限 ±40%。
- **护盾**吸收伤害优先，回合结束不保留。

### 5.4 单位属性

| 属性 | 说明 |
|---|---|
| HP | 生命；归零退场 |
| ATK | 攻击力 |
| SPD | 交兵期行动顺序 |
| RNG | 射程：`near` 近战 / `far` 远程 |
| Cost | 墨费（1–8） |
| Keywords | 词条（见 5.7） |

### 5.5 合契（3 同名 → 升星）★自走棋核心

- 场上/手牌中凑齐 **3 张同名灵契卡** → 自动**合契**，合成 **★+1** 的单位（1★→2★→3★，上限 3★）。
- 升星效果：**HP/ATK 约 ×1.8（2★）/ ×3.2（3★）**，并在 2★/3★ 各**解锁一个额外词条或强化现有词条**。
- **合契不可逆**，且需要 3 张同名的同阶卡 → 形成"囤卡还是铺场"的核心取舍。

### 5.6 羁绊（双维度）★原创

单位同时携带 **系（element）** 与 **源（origin）** 两个标签，两套羁绊独立计算：

**系（八系）**：木 / 火 / 土 / 水 / 金 / 日 / 月 / 灵。档位 **2 / 4 / 6**（不同"系"上场的**不同单位数**）。
- 例：木 2 → 全体木系单位 ATK +10%；木 4 → +20% 且回合开始回复墨 1；木 6 → +30% 且交兵期先手。

**源（四域）**：庭（春庭）/ 海（夏海）/ 岭（秋岭）/ 宫（冬宫）。档位 **2 / 4**。
- 例：宫 2 → 全体获得 3 点护盾；宫 4 → 护盾 8 点且免疫「缚」。

> 双维度是构筑的深度来源：一套牌要同时算清"系够不够 4 档、源要不要凑 2 档"。**这是本作与既有作品最大的机制差异点。**

### 5.7 词条（Keywords，原创中文命名 + 英文对照）

| 中文 | 英文 | 效果 |
|---|---|---|
| 固守 | Bulwark | 敌方必须先攻击本单位（嘲讽） |
| 疾行 | Swift | 部署当回合即可行动（冲锋） |
| 初啼 | Omen | 部署时触发一次效果（战吼） |
| 遗响 | Echo | 退场时触发一次效果（亡语） |
| 贯 | Pierce | 攻击溢出的伤害传递到同列下一单位 |
| 守 | Ward | 免疫一次伤害（圣盾） |
| 摄 | Siphon | 造成伤害时回复等量 50% 于自身（吸血） |
| 缚 | Bind | 目标本回合无法行动（冻结） |
| 连 | Rally | 相邻同列友方攻击时，本单位追加一次普攻 |
| 岁守 | Yearguard | 免疫「缚」与位移 |

### 5.8 平衡验证（AI 开发友好）★

- **无 PvP** → 平衡可用**离线自动对局模拟器**验证：给定两套卡组/阵容，纯逻辑跑 10⁴ 局，输出胜率曲线与回合曲线。
- 战斗逻辑**必须与渲染解耦**：`UBattleSubsystem` 可被命令行工具直接驱动（无 Tick、无 UWorld 依赖）。这是**硬性架构约束**。
- 数值调整以模拟器产出为准，写入本文档附录（`docs/BALANCE.md`，后期建立）。

## 6. 节气天时（原创核心变量）★

**当前节气 = 本局的天时**。每推进 1 个节点，节气前进一格（24 格一轮回）。

| 天时效果 | 说明 |
|---|---|
| **卡池偏向** | 本季所属「系」的卡在坊市出现率翻倍；对立季的卡出现率减半 |
| **系加成** | 本季对应系（春=木 / 夏=火 / 秋=金 / 冬=水）的羁绊档位需求 **−1** |
| **天气词条** | 节气附带一条全局词条，例：惊蛰（全体疾行）/ 夏至（所有火系 +20% ATK）/ 霜降（回合末全体受 2 点霜伤）/ 冬至（所有回复效果 −50%） |
| **节气主** | 每 6 个节点一位节气主，其阵容固定绑定该季，玩家的天时优势在此被抵消 |

> **设计意图**：让"同一套构筑在不同节气下是两副牌"，从而在不做 PvP 的前提下获得长线变数与重玩价值。

## 8. 技术架构（虚幻引擎 5 · 2.5D）

```
solstice/
├─ game/                       # 虚幻引擎工程（Solstice.uproject）
│  ├─ Source/Solstice/
│  │  ├─ Core/                 # GameInstance / 存档 / 事件总线 / 数据加载

│  │  ├─ Board/                # 岁盘：2×6 布阵区、站位、寻敌
│  │  ├─ Run/                  # 岁局：地图生成、节点推进、经济、天时
│  │  ├─ Meta/                 # 局外：岁印、解锁树、岁劫难度
│  │  ├─ Sim/                  # 离线自动对局模拟器（命令行可跑）★
│  │  └─ UI/                   # UMG C++ 基类（蓝图做表现层）
│  ├─ Config/  ├─ Content/  └─ Plugins/
├─ studio/                     # 本地生图线（ComfyUI + FLUX.2 Klein）
├─ shared/                     # 契约：JSON Schema（引擎与生图线共读）
├─ tools/                      # 环境安装 / 工程生成 / 构建 / 模拟器脚本
├─ docs/                       # DESIGN / STORY / ART-STYLE / STRUCTURE / ENV / SYNC
└─ .vscode/                    # VSCode 开发配置
```

**硬性技术约束**
- **战斗逻辑零渲染依赖**：`UBattleSubsystem` + `UBoardSystem` 不得依赖 Tick / 渲染 / 玩家输入，可被 `USolsticeSimRunner` 纯逻辑批量驱动（§5.8）。
- **2.5D 相机**：固定斜俯视角（约 45° 俯角、近正交感、不跟手旋转）；探索/战斗共用同一相机语言。
- **卡通特殊风格**：自定义 Toon 着色（分层色阶 + 描边 + 纸张颗粒）；**不以 Lumen/Nanite 为卖点**，优先可控性能与风格稳定。
- **性能预算**：1080p / 60fps @ RTX 5060 级 8GB 中端独显；2.5D 固定机位使预算可控。
- **UI**：UMG；中英双语。
- **存储**：`USaveGame` 版本化迁移；键 `solstice.save.v<n>`。
- **素材外置**：`Content/` 二进制不入 git（走管线再生或可选 LFS），契约与 manifest 入库。

## 9. 素材线（本地生图）

- **风格锚 C1「纸墨卡通」**：Cel-shading、强剪影、大色块、墨线描边、纸张/版画颗粒；四季各一套受控色板。
- **规格**
  - 灵契卡立绘：**1024×1024**，单主体居中，**纯色 chroma 底**（便于抠图，模型无 alpha 通道）。
  - 卡面：**1024×1365（3:4 竖版）**，**画芯无文字无边框**（边框/角饰/系徽/数值由 UMG 统一绘制）。
- **量产**：ComfyUI + FLUX.2 Klein 4B FP8；工作流与 prompt 库见 `studio/`。
- **合规**：逐张留档（模型 / prompt / seed / 日期）→ `studio/out/manifest.jsonl`，并写入卡数据的 `credits`（Steam AI 内容披露）。
- **一致性**：每批以风格锚图为参照；每批出 QC 表由用户裁决挑图。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| **融合变成四不像** | 每个机制必须在 M1–M3 各自被验证"单独好玩"再合并；任一机制若不能通过 5 分钟上手测试就砍掉 |
| 引擎切换成本（旧资产已全删） | 旧的**设计资产**（节气日历、包系统思想、生图管线）以文档与 schema 形式转世，而非代码 |
| 2.5D + 卡通风格实现难度 | M0 先用 PostProcess/Custom Node 验证观感再决定是否自研 Toon 材质；风格不定标不进 M2 |
| AI 无法操作 UE 编辑器 GUI | 系统逻辑全走 C++；蓝图仅做薄表现层，每个蓝图给"连线说明书"（`game/BLUEPRINT-GUIDE.md`） |
| 单机无 PvP → 平衡无真人数据 | 离线自动对局模拟器（§5.8）；**这是本作最关键的工程投入** |
| 数值体系返工 | 数值全部数据驱动（JSON/DataAsset），改数不改码 |
| 美术量爆炸（卡 300 张） | 卡面由生图管线量产 + 风格锚锁定 + QC 清单；立绘复用主体，边框由引擎绘制 |
| 肉鸽重复度 | 天时 + 双维度羁绊 + 事件随机池，保证每局构筑分化 |
| 过度工程化 | M0–M2 不做工坊/不做模组/不做多人；schema 只加不改 |
