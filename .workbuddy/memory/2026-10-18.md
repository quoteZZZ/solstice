# 第二轮（同日，接上一节「下一步 1→2」）

## 做了什么

**D-04 天空已经是完成态**（`a78e3a0` 之后），于是接第 2 项「水体看不见」，量出来是**两个真 bug**，不是配色：

1. **水域 0.0%（0 格 / 16384）**。旧代码按**绝对阈值** `H01 < 0.18` 切海岸线，而 `ridges` 的
   噪声（`1-|2N-1|`）分布几乎从不落到 0.18 以下 → 一格水都没有。
2. **峰高只到 23.2 m**。`Height = 2 + Shaped*(64-42)` 的上限是 24，而配色坡道按 64 归一 →
   四条色带只用到两条（silt/grass/meadow），岩带和山相永远不出现 = "一块绿饼"。

改法（`Sim/SolsticeKernel.cpp::GenerateTerrain`）：
- 先算全界 `H01` 存 `TArray<float> Raw`，排序取**百分位**：`TargetWaterFraction01 = 0.14`
  以下为海床（1 m → 水位−0.25），其余按 `(N−SeaCut)/(PeakCut−SeaCut)` 重映射到
  `水位 7 m … TerrainPeakMeters 26 m`，再走 `TerrainShapingExponent`。
  **峰取 99.5 百分位而不是 max**——一个噪声尖顶会把别的山全压平。
- 渲染侧（`Gen/SolsticeGenerators.*`）：水色 `#4E9BC0`/`#1E5B86`（深水原 `#123061` 与界外空场
  `#0B1431` 几乎同色，所以"海面 = 世界到此为止"）；新增 `Surf`/`Ripple` 两色，
  **岸线亮边**（水侧 35 cm，抬 2 uu 防 z-fight）与**静态波纹线**（开阔水 1/7 格）；
  地形色带除法 `/MaxHeightMeters` → `/TerrainPeakMeters`。
- `bench` 新增**地形普查**（`FTerrainCensus`）：海拔 min/max、水域 %、岸线格数、八档高程分布。
  这是这次能三分钟定位的原因——之前"没水"和"水被地形盖住"只能靠猜。

# 第三轮（同日）· 世界外缘

## 做了什么

外缘是三个独立缺陷叠在一起，逐个量出来：

1. **底座是"沙色托盘"**：`BuildBase` 用 `Kraft = CutEdge*0.86`（米色）、顶盘半径 = R（比撕裂后的地形大）

   改成**与地形同一条切线**（同一 `Gen::TornRadius`）、厚度 `Radius*0.03`、墙/底同色。
2. **外缘 1 m 台阶**：地表按格心剔除。改成按**角**判（全在内 → 原路；穿过 → 用
   `ClipPolyToDisc()` Sutherland-Hodgman 裁到圆，扇形发出）。边界格上的草/花/树/石/水边一律跳过。
   顺手删掉那段 `Out.Wall(P0,P1,TopZ,TopZ,…)` **零高度残墙**（注释说"切线画在 BuildBase"，其实没画）。
3. **切口穿过山体 = 20 m 黑幕**（第一次改完就是这个后果，抓帧立刻看到）。真源冲突的解法：
   地形在 **0.84–1.0 R** 平滑收到水位以下（`TerrainRimDropBelowWaterMeters = 0.4`），
   山留在盘内、边缘是水。**同时水位 7 → 3 m**（`world.json` 7 处）、海床 0.5 m、
   深水色深 2.5 m——水位不降，切口厚度必然 ≥ 水位。
4. **满天小石块**：巨石写的是 `Centre + FVector(0,0,Surface*MeterUU)`，而 `Centre` 的 Z
   **已经是** `Surface*MeterUU` → 每块石头悬在两倍地面高度。这是从第一轮就在的"碎点"，
   之前一直误判成"界外立牌"（`BuildLife` 也确实没按半径剔除，一并补上）。
5. 曝光 `0.60 → 0.75`：中位 0.416 → 0.465（进 0.45–0.60）。

## 这轮最重要的发现：**短板不在我以为的地方**

上一轮我以为「岛最糙」，测量说反了 —— 岛其实是细节最多的地方。

## 根因（机制，不是参数）
波浪只作用在**法线**上。近海俯视角 3–30°：Fresnel≈0（不反射天空）、高光方向背对
（不出现太阳反光）。**反射与高光都不在那里成像**，只剩一层均匀自发光 → 44% 画面没有信息。

## 做了什么
1. `M_Sea` 新增 `WaveDetail` Custom 节点：与 `WaveNormal` **同方向同相位**的波高场
   （高度场与它的梯度必须一致，否则高光会和明暗错位）。打包 `(height, foam, 0)`，
   用两个 `DotProduct` 解包——不需要新增节点类型。
2. 波高调制**水色本身**：`Tex * (1 + height * WaveShadeAmount) * (1 - Fresnel)`。
   最后那个 `(1-Fresnel)` 是必须的：远海是镜面，否则它的水体会浮出一层条纹。
3. 浪尖白沫：同样按 `(1-Fresnel)` 门控。**阈值 0.42 太高，一朵都没出现过**；0.24 才行。
4. `chop` 从「再加两层正弦」→ **各向同性 value noise**（Hoskins 哈希）。
   正弦是平面波，叠加必然塌缩成一个主方向。
5. 云：`lit` 幅度 ×10 → **×26**（原幅度只有 ±0.05，等于剪影）；覆盖度用第二采样 `m`
   做低频调制 → 大团簇 + 小云并存；云底按仰角压暗（积云平底）。

## 两条度量教训（重要，避免下次再误判）
1. **block-std / 拉普拉斯对「低频大图案」不敏感**。3.3 m 的波在近处屏幕上 155 px，
   16px 的块只跨越 10% 个波长 → 数字几乎不动，但眼睛看得见。要量「有没有内容」，
   得同时看**梯度幅值**和**分频带能量**，不能只看一个。

   压扁 → 纵向梯度天然远大于横向。我一度据此断定「木纹」，改了两轮正弦权重全白费。

# 第十四轮（继续分析需求与不足 → 方向光）

## 这轮最硬的一个发现
岛上大尺度明暗的**方向集中度 R = 0.006**（0 = 完全各向同性，1 = 单一方向）。

- `SunLight` 的 intensity 单位是 lux 量级，我设 4.6

# 第十五轮（用户「继续」→ 发现地形**从未受过光**）

## 一句话结论
上一轮记的「水面接不到投影」是**误判**。真正的缺陷在更上游：**M_Cel 的顶点色同时接到了
EmissiveColor**，所以岛的颜色是直出的，太阳和天光都改不动它一个像素。修掉之后画面的光照
第一次真正成立，整条光照标定（14 / 0.10）随之作废并重定。

## 怎么发现的（顺序，值得复用）
1. 先按上一轮的假设去调水的 `WaterDiffuse`/`WaterGlow` → 两张图肉眼几乎一致，**起疑**。
2. 做隔离实验：`-Env "1,0"`（关天光）→ 岛亮度只掉 1.3%；`-Env "0,0"`（两路光全关）
   → **岛和海一样亮**。到这里可以断定「材质不受光」，不是「光不够」。
3. `gen-assets` 提示 `master materials at recipe v49` = 没重建，于是 bump 版本强制重建
   → 仍然不受光 → 说明不是「资产滞后」。
4. 在 `BuildCel` 末尾把资产读回来打日志：
   `[diag] M_Cel model=2 blend=0 two_sided=1 base=1 **emissive=1** rough=1 spec=1 nodes=4`
   —— 只 Add 了 4 个节点却 `emissive=1`，**这就是全部答案**。

## 根因
`Material->GetExpressionCollection().Empty()` 只清节点数组，**不清
`UMaterialEditorOnlyData` 里各输出的 `Expression` 指针**。于是重建时没显式赋值的输出
（EmissiveColor / Normal / Opacity…）会**继承上一版资产的连接**，而这个指针指向的节点
已经不在图里。M_Cel 从 unlit 改成 lit 的那次重写把 Emissive 漏了，从此顶点色既当 albedo
又当自发光 —— 表现是「看起来被照亮、但对任何光都不响应」，和光照 bug 完全无法区分。

修法：新增 `FSolsticeCelMaterialBuilder::ResetGraph()`，清节点后**按反射把所有
`F(Material)Input` 类型的 UPROPERTY 置空**（按 struct 名字匹配，因为这些是
`USTRUCT(noexport)`，`IsChildOf` 不可靠）。五个材质全部改走它。
资产体积 11376 → 6357 B（少的就是那截残留）。

## 顺带修的四个真 bug
1. **阴影级联覆盖不到岛**：`DynamicShadowDistanceMovableLight` 默认 20000 uu = 200 m，
   而机位离世界中心 **213 m** → 整个岛在最后一级阴影之外。`SetCastShadows(true)` 是真的、
   网格投影也是真的，**画面上就是没有阴影**。→ 90000（900 m）+ `CascadeDistributionExponent 2.2`。
2. **道具不投影**：`PropMesh->SetCastShadow(false)`，120 棵树/石全是贴纸。→ true。
3. **接触阴影在远景大面积误遮蔽**：`ContactShadowLength` 是**屏幕空间**比例，0.06 在 213 m
   外的地形上是极长的世界射线。已置 0（关掉），等有近景机位再按 preset 调。
4. **`shot.ps1` 一直在吞 Log 级诊断**：UE 日志里只有 Warning/Error 才打印级别词，
   Log 级的行是 `LogSolstice: [diag] ...`（没有 `Log: `），而脚本正则要求有级别词。
   → 正则加可选分支。**之前所有 `[diag] sun:` / `[diag] chunk` 从来没显示过。**

## 新增三个「一次运行」调试口（省掉一轮 25 s 编译 + 40 s 抓帧）
`FParse::Value` 的 `bShouldStopOnSeparator` 默认 **true，遇逗号就截断**（第一版三个开关
全部只读到第一个数）。必须传 `false`。
| 参数 | 含义 |
|---|---|
| `-SolsticeEnv=<sun>,<sky>,<exposure>` | 太阳/天光强度乘数、额外曝光档（-1 = 不动） |
| `-SolsticeSea=<diffuse>,<glow>,<shade>[,<foam>[,<specular>[,<reflect>]]]` | 水材质六项配平 |
| `-SolsticeCel=<gain>` | `SurfaceBaseGain`：地表 albedo 增益，用来区分「暗」与「不受光」 |

`-SolsticeCel 0` 抓出来是**纯黑剪影** —— 这就是「材质链路通畅」的判据，比看十张图快。

## 重新标定的值（全部有实验支撑）
| 项 | 旧 | 新 | 依据 |
|---|---|---|---|
| `SunLightIntensity` | 14 | **100** | 14 时岛近黑；40 偏暗；120 过曝（mid 0.712 FAIL）；100 三项 PASS |
| `SkyLightIntensity` | 0.10 | **1.0** | 0.10 时关掉天光只掉 1.3% 亮度 = 等于没有 |
| `WaterDiffuse` | 0.18 | **0.05** | 0.18 在 560 单位太阳下把海打成青白 |
| `WaterGlow` | 1.0 | **0.80** | 水比受光的岛还亮，画面没有明度阶梯 |
| `WaterSpecular` | 0.45 | **0.16** | 太阳反光铺满近海，mid 0.682 FAIL |
| `SkyReflectStrength` | 0.75 | **0.50** | 掠射带比它反射的天空还亮 |
| `FoamAmount` | 0.32 | **0.15** | 0.32 时是「白色横向条带覆盖水面」= 丝绸感的主因 |

## 一个必须记住的取舍
**自发光面接收不到阴影。** 水面为了「水色恒定、正午不过曝」必须走 emissive 主导，
所以**岛的影子不会落在水上**，这不是 bug。想两者兼得只能上 Single Layer Water 或
translucent + shadow volume，代价是水色随光变。**风之杖/原神的水面同样没有岛影。**

# 第十六轮（同日）· 云的边缘与厚度

# 第十七轮 · 用户实际打开游戏后："太丑了，无法正常看下去"

用户给的截图是**真实运行**（PIE + HUD），和抓帧完全不是一回事。三个独立问题：

## 1. HUD 遮了三分之一的画面（"无法正常看下去"的直接原因）

## 2. 开局是**晚上**（用户正好 21 点打开）
`FSimKernel::Initialize` 在 `StartingMinuteOfDay < 0` 时取 `FDateTime::Now()`，
只有 22:00–05:00 才回退到 06:30。**20:00 落在"允许"窗口内，而这个天空模型把 20:00
算成太阳在地平线下 30°= 全黑。**
→ 窗口收成 **09:30–16:00**，窗口外一律 09:30。
（更早试过 08:30–17:30，但 08:30 的画面整片过曝，见下条。）

## 3. 夜间 / 清晨画面失真（三个各管一段的错）
| # | 症状 | 真因 |
|---|---|---|
| a | 夜间**云是纯白**，是全画面最亮的东西 | `CumulusLit` 夜间值写的是**线性 (0.42,0.46,0.54)**，再乘 `SkyDim = 0.5^-1.15 = 2.22` → 出屏 0.93。**改成 `CelSrgb(0x36,0x4C,0x68)`** |
| b | 夜间**太阳落山 30° 还在用 15 的强度照地面** | `Lerp(0.15,1,...)` 的下限 0.15 是"黄昏余晖"，夜间没归零；而且方向朝上，照亮岛底。→ 加 `SunUp` 门（-3°/+2° 之间线性），归零后**切换到月光**（反日点、冷蓝、80） |
| c | 夜间**海比天空亮 3 倍** | 海是 emissive，`NightSea` tint (0.20,0.26,0.42) × SkyDim 2.22 太高。→ (0.05,0.09,0.17)；`SkyReflectStrength` 夜间 0.5→0.22 |
| d | 夜间月光大道太宽太白 | `WaterSpecular` 夜间再降；夜间 0.006 |

**"夜里岛是一块黑"不是夜色，是 bug**：`Ambient01` 下限只有 0.06（+ SkyLight 实际无贡献），

## 4. 水面高光：一个参数吃掉整个下半屏（最重要的一条）
09:30 整片海 (255,255,255)。**逐档实测 midpoint 对 `WaterSpecular` 的敏感度**：
```
0.16 -> 0.912   0.08 -> 0.792   0.02 -> 0.633   0.01 -> 0.576   0.00 -> 0.424
```
线性、且是"海"和"白纸"的全部差别。取 **0.01**（`WaterRoughness` 0.38→0.46）。
**正午之所以一直是好的，只是因为它太阳在头顶、反射方向避开了相机** —— 换个时刻立刻现形。

**踩坑**：改材质默认值之前先确认**没有别处每帧覆盖它**。`PaintSea()` 里有一行
`SeaMID->SetScalarParameterValue("WaterSpecular", Lerp(0.04,0.08,Daylight))`，
把材质里精心调的值整个覆盖掉 —— 第一次把材质 0.16→0.08 时画面变化来自别的原因，白改一轮。

**代价要记住**：太阳 100 下 specular 0.01 意味着水面几乎没有阳光碎光。
想要波光只能另想办法（低太阳+低强度，或单独的、明确 clamp 的加性 glint 项），**不能把这个数调回去**。

## 5. 棕色裸岛（用户截图里的另一半）

# 第十八轮 · 用户："太烂了"——这次是形态问题，不是参数

## 诊断
之前十几轮全在修 bug（材质不受光、HUD、夜间、高光），但**画面构成本身**还是
"远处一个沙洲 + 平面海 + 平面云"。用户看到的不是 bug，是**形态**。

bench 给了根因：`height bands 0-8: 90.2%` —— **九成陆地在前 8 米内**。
128 m 的岛、21 m 的峰，平均坡度 16°，这在几何上就是个沙洲加一个包，
再好的材质也救不回来。**岛要有崖。**

## 做的四件事（都有数字）
1. **地形剖面抬陡**：`HTab` `{0,.032,.072,.132,.212,.300}` → `{0,.070,.155,.250,.350,.450}`
   （×Relief0.94×半径64m）。峰 21.2 → **29.5 m**，`0-8m` 占比 90.2% → **77%**，
   `16-24m` 2.8% → 4.7%，`24-32m` 0% → 2.7%。**digest 变了是预期的（世界真的变了）。**
2. **相机拉近**：preset 0 `Fit*0.80 → 0.60`，pitch `-1.8 → -2.6`。
   岛从"画面 1/3 宽的远景"变成主体，海岸线和浪进入景深清晰区。
3. **地表斑驳**：M_Cel 新增 `GroundDetail` Custom 节点（世界坐标 3 octave value noise，
   两个尺度：~50 m 与 ~6 m），输出 `lerp(Damp, Dry)` 乘到 albedo。
   一整片 `#7FBF5F` 是"塑料模型"的最大来源，现在每个坡面有自己的草地。
4. **水面波长跟随相机**：`WaveScale 0.00032 → 0.00058`（相机近了 25%，波长按比例补偿），
   `hn` 权重改为 `swell*0.60 + chop*1.35`（噪声主导，压制方向波的横向条带）。

## 两个失败的尝试（要记住）
- **降低后处理饱和**（1.18 → 0.96）：画面只是变灰变脏，没有变"高级"。
  高级感来自**光的方向和大气透视**，不是降饱和。
- **把 GoldenWindow 从 14° 放宽到 26°** 想让下午变暖 —— **天空直接变紫**。
  `DuskZenith/DuskHorizon` 是一套紫灰暮色，提前混合只是把暮色倒进正午。
  已回退（14°）。**窗口大小是对的，错的是黄昏色板本身。**

## 验证
```
bench : 0-8m 77% / 8-16m 15.6% / 16-24m 4.7% / 24-32m 2.7%，峰 29.5 m
frame : 0.327 / 0.533 / 0.011  三项 PASS（09:30，preset 0）
```

## 还差什么（下一轮的正确路径，不再是调参）
1. **树只有一种形状**（伞状 cushion），铺满山坡就是"蘑菇林"。需要 3-4 种树形 + 随机缩放。
2. **云是 2D 噪声投影**，没有体积。要 raymarch（视线积 4-6 步）或 2.5D 多层。
3. **地表没有几何细节**：斑驳只在 albedo，草叶/碎石不存在。
4. **色板本身是高饱和卡通风**（`#7FBF5F` 这种纯绿），要"壁纸感"得重做一版低彩度色板，

# 第十九轮 · 贴图系统落地（用户："需要用贴图、渲染，想看 4K 动漫截图"）

## 架构：仓库不存二进制资产，所以贴图走「Python 生成 → 运行时解码」
```
tools/art/gen-textures.py     numpy 生成可平铺 PNG（512²）
  -> tools/art/textures/*.png 提交进仓库（文本能过的就是 PNG）
  -> SolsticeCelMaterial.cpp  ImageWrapper 解码 -> UTexture2D::CreateTransient
  -> MID->SetTextureParameterValue("GroundAlbedo"/"RockAlbedo"/"SandAlbedo")
```
**不生成 uasset**：uasset 被 gitignore，且无 RHI 的 commandlet 导入不可靠。
好处：改纹理只要重跑 python + 重启进程，**不用编译、不用 gen-assets**。

材质里 `DetailBlend` 是一个 Custom 节点，按顶点色做**分类**（绿=草 / 黄=沙 / 其余=岩）
而不是三路混合——混合会把三种表面平均成一片灰，正是要修的病。

## 三个坑（都会让画面出现"白纸岛"）
1. **`TextureSample.Coordinates` 只收 float2**，直接连 WorldPosition（float3）会
   `Cannot cast from larger type float3 to smaller type float2` → **整个材质编译失败**，
   回落 `DefaultMaterial`（白）。必须先 `ComponentMask` 取 RG。
   **判据**：日志里 `LogMaterial: ... Failed to compile Material ... Default Material will be used`。
2. **`FImageUtils::ImportBufferAsTexture2D` 在启动阶段返回的纹理 platform mips 为空**，
   采样恒白（日志还显示 512×512，完全看不出来）。改 `IImageWrapperModule` 手动解码 +
   `CreateTransient` + 填 BulkData。
3. **改了材质图必须 bump `CelRecipeVersion`**，`gen-assets` 只看版本戳。
   这轮又是先漏了一次（recipe 64 没重建，白跑一轮编译）。

## 调色

- `bHigh`（岩石起始高度）11 m → **20 m**：峰已抬到 29.5 m，11 m 阈值把岛上三分之一

# 第二十轮 · 修白树干 + 性能测量

## Bug：树干是白的（上一轮遗留）
**根因不是着色，是结构**：`AddTree` 里 `AddTrunk(...)` 写在 `Family` 判断**之前**，
所以每一丛灌木都被插了一根 **2–4 m 的细杆**——那一排白杆就是它。
删掉这次调用（灌木不该有树干），白杆消失。

**教训**：我为了这个白杆查了三轮顶点色/材质/贴图分类，全是错的。正确的一步是
**先问"这个物体到底该不该存在"**，而不是"它的颜色为什么不生效"。几何上不该有的东西，
调它的颜色永远调不好。

顺带修掉 `BuildChunk` 里那套树的树皮：原来用 `Palette.CutEdge * 0.52`（纸片切边的浅米色
`#DBD1BD`），等于给树干刷白漆；改成线性 `(0.030, 0.019, 0.011)`。

## 性能：先能测，再优化
- 新增 `[diag] perf: avg %.2f ms` —— 放在 `Tick` 里**每帧**累加，30 帧报一次。
  （第一版放进了 `DiagCalls % 120` 的节流块里，采样率塌到 1/100，平均无意义。）
- 新增 `[diag] props: verts/tris` —— 道具是独立 mesh，从来不出现在 per-chunk 行里。
- `shot.ps1` 加 `-ExecCmds=r.VSync 0`，否则测到的是刷新周期不是渲染耗时。

**实测（1280×720，preset 0）**：
```
帧时间  16.13 ms / 62 fps（稳定段）；前 30 帧 30 ms 是着色器编译
地形    184,902 三角形（4 块：44.7k / 41.1k / 41.5k / 57.6k）
道具    228 三角形（岛上绝大多数树是 BuildChunk 画的，在地形三角形里）
```
62 fps 说明**不卡**。注意：即使加了 `r.VSync 0` 仍是 16.13 ms，这是离屏抓帧模式的节奏，
不是 GPU 上限 —— 真实上限需要跑带窗口的会话才测得准，已记在这里免得下次误读。

## 本轮的三项优化
1. **阴影距离 900 m → 400 m**：900 是相机在 213 m 时定的，现在相机 160 m，400 m 覆盖
   世界 + 近岸还有余量；2048 texel 摊到 400 m 是 20 cm/texel（原来 44 cm），**精度翻倍、开销不变**。
2. **删掉重复的树木生成**：上一轮我加的 `AddTree` 和 `BuildChunk` 里已有的树是两套，
   同时跑等于把同一件事做两遍。现在 `AddTree` 固定 `Family = 2`（只画灌木），大树交给 `BuildChunk`。
3. **灌木不再插杆**：120 个个体 × 12 三角形。

# 第二十一轮 · 画面：天空方向性、海面微波纹、云的投影

用户「完善优化画面效果」。这一轮没有修 bug，全部是**画面构成**，四块各管一段。

## 1. 天空从来没有方向感（最大的一项）
之前的天空是**纯垂直渐变**：颜色只是仰角的函数。太阳在画左还是在画右，天空一模一样。
实测：整幅 1280px 宽的天空亮度变化 3%（= 噪声）。

加了**三个幂次的太阳散射项**（`pow(mu,3)` 宽 60° 打亮整个向阳半天空、`pow(mu,24)` 塑形、
`pow(mu,160)` 日面），再加**地平线大气带**（视线横穿 ~38 倍大气质量 → 更亮更暖）：
```
sky += SunHalo * pow(mu, 3.0) * 0.09;
sky += SunHalo * pow(mu, 24.0) * 0.15;
sky = lerp(sky, Horizon + SunHalo*0.10*mu, pow(saturate(1-h*2.6),4.0) * 0.24);
```
第一版 0.16/0.20/0.30 **过曝成灰白**（饱和度掉到 0.306，天是白的不是蓝的）→ 收到 0.09/0.15/0.24。

## 2. 海面：三个层次的问题，三个不同的修法
| 现象 | 真因 | 修法 |
|---|---|---|
| 横向平行条纹（"丝绸"） | 4–5 个**固定方向的平面波**，波前是平行直线，透视一压缩就是横条 | 采样前做 **domain warp**（`p + 噪声/正弦偏移`）让波前弯曲；再加一层 **78 m 超低频涌浪**给近处大形状 |
| 全画面"糊、平"，没有水的质感 | 所有细节都在 **2–78 m**，而最近的可见水面在 **33 m** 外 → 最细的一层也是 80 px | 新增**亚米级微波纹**（0.38 m 格点的随机斜率场，3 octave） |
| 微波纹出来后有**菱形网点** | value noise 在格点处是常数，**格点可见成网格**；2 octave + smoothstep 更明显 | 格点 0.55→0.38 m、**quintic 插值**、3 octave、幅度 2.4→1.5 |
| 大尺度明暗变成"污渍" | 78 m 涌浪作为**明暗项**时，一个波峰占画面 1/5，读作污渍不是波 | `hn = swell*0.28 + chop*1.25`（大尺度只做很弱的整体起伏，波峰交给法线和轮廓） |

**海面还要压暗**：实测海 mean 0.58 / 天 0.63 —— 差 5%，整个画面因此没有明度阶梯。
`WaterGlow 0.80 → 0.62`。

## 3. 云：投影分母是最关键的一个数
| 分母 | 效果 |
|---|---|
| `0.30`（原来） | 可见天空里云半径只变化 **1.9 倍** → 云像贴在同一个球壳上，且出现**从正上方放射的条纹**（噪声只沿一个轴被压） |
| `0.10`（真物理平面层） | 半径变化 4.4 倍，**但**这个机位只看到 0–15° 仰角，1/h 投影把每朵云压成几像素高的横条 —— 物理正确、视觉不可用 |
| **`0.55`（采用）** | 半径变化 1.5 倍，有透视但云保住自己的形状。**风格化的云层，不是物理的**；不 raymarch 就只有这一条路 |

配套：`CloudScale 2.4 → 3.8`（补偿投影变软）、`CloudThreshold 0.55 → 0.44`（覆盖率 14%→30%）、
`mask` 过渡带 0.24→0.28（上限是噪声动态范围 ~0.30）。

**云的斜向刷痕，两个错误版本**：
1. `sin(cp.y)` 偏移 x + `sin(cp.x)` 偏移 y = **剪切**，整个场沿一条对角线拉长。
2. 改成 `sin(a*y)*sin(b*x)` 乘积 —— **还是错**：它等于 `0.5*(cos(ay-bx) - cos(ay+bx))`，
   依然是两列平面波，只是转到对角线上了。
3. 最终：**用 value noise 做 warp**（1 octave，4 个 hash）。**任何正弦组合都有轴，噪声没有。**

**云的大块直边**：value noise + **smoothstep 插值**是 C1 不是 C2，格线处**梯度不连续**，
阈值一卡就贴着格线跑 → 比一个格点大的云会变成**倾斜四边形**。改 **quintic** 解决。

## 4. 穹顶细分：插值弦误差
`d = normalize(WorldPosition - CameraPosition)`，而 WorldPosition 在三角形内是**线性插值**
（球面的弦不是弧），于是每个三角形边缘有一个折痕。对平滑渐变无害，对**阈值化**是致命的：
画面上出现和穹顶三角形一样大的、直边多边形色块（右上角）。
`128×64 → 256×128`（矢高降 4 倍，色块小于一像素；65k 三角形对 unlit 天空无所谓）。

## 5. 岸线的"梳齿"
草叶原来从 `Surface > 1.0` 就长，**贴着水线**：背景是海不是草，每格三根细尖 → 一排 20–30 px 的针。
改 `> 2.4`（沙滩归沙滩）、高度 0.34–0.96 m → 0.22–0.60 m、**单三角改交叉双三角**
（单面片侧看是一条线，一半的草会"消失"）。

## 6. 树：冠高比
`TrunkHeight 120+120 / CrownRadius 90+70` → `90+80 / 130+100`。原来 3.6 m 的树配 1.3 m 的冠 =
棒棒糖，在 20 px 高度上就是蘑菇。**树线止于 24 m**（峰 29.5），山顶留裸岩。

## 工具坑
- **`TEXT(R"(...)")` 是宽字符串，MSVC 上限 8192 字符**（不是窄字符串的 16380）。
  超了报 `C2026`，中文 locale 下显示成乱码，读起来像语法错误。
  修法：拆成相邻字面量 `TEXT(R"(...)") TEXT(R"(...)")`（编译器自动拼接）。
  这一轮 M_Sky 撞了两次（8254、8510）。**加 HLSL 代码前先量长度**：
  ```python
  import re; s=open(p).read()
  for m in re.finditer(r'R"\(', s):
      print(len(s[m.end():s.index(')"', m.end())]))
  ```
- `shot.ps1` 新增 **`-Quiet`**：只出量化结果，不回显 `[diag]`。抓帧日志现在会刷屏。
- **改材质默认值前先查有没有每帧覆盖**：`PaintSea`/`PaintSky` 里覆盖了
  `WaterSpecular` `SkyReflectStrength` `SeaTint` `CloudThreshold` `CloudScale` `CloudDrift` 等。
