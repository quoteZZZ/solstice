### 本机关键环境事实（踩过的坑，别再重复）

- 引擎 `D:\Epic Games\UE_5.8`（**5.8.3**，CL 58210709）；VS2022 生成工具 `D:\VS2022`（MSVC 14.44.35207 + Windows SDK 10.0.22621.0）。
- **编译必须加 `-NoUBA`**：UBA 的文件系统 detour 在本机每个临时文件改名都 `Access is denied`，导致 PCH 报 `C1083 拒绝访问`。沙箱内外都复现过，不是 agent 策略。`-NoUBA` 是 UBT 正式开关（`BuildConfiguration.cs:54`）。
- **不要直接跑 `UnrealBuildTool.exe`**（本机只有 .NET 8/9，会 `EXIT=150`）。必须用引擎自带 .NET 10 挂 DLL：
  `D:\Epic Games\UE_5.8\Engine\Binaries\ThirdParty\DotNet\10.0\win-x64\dotnet.exe UnrealBuildTool.dll <Target> Win64 Development -Project=... -NoUBA -WaitMutex`
- **`.NET Framework 4.6.2 SDK`** 已补齐到 `D:\_toolchain\AutoSDK\HostWin64\Win64\Windows Kits\NETFXSDK\4.6.2`，并注册 `KitsInstallationFolder`（HKLM WOW6432Node + HKCU）。从本机 VS 渠道清单 `C:\ProgramData\Microsoft\VisualStudio\Packages\_Instances\<id>\catalog.json` 取官方包并校验 SHA256。`SwarmInterface.Build.cs` 没它会直接抛 `Could not find NetFxSDK install dir`。
- **`UE-LocalDataCachePath` 已设为 `D:\UE-DDC`**（用户级环境变量，目录已建）。它**确实是环境变量**——`BaseEngine.ini:2866` 的 `EnvPathOverride=UE-LocalDataCachePath` 与 `:2726` 的 `LocalDataCachePathEnvOverride=UE-LocalDataCachePath` 都认它。实测日志 `LogZenServiceInstance: Found local data cache path=D:/UE-DDC`、`data dir 'D:/UE-DDC/Zen'`。
- 编辑器进程会占 Live Coding 互斥锁（`Unable to build while Live Coding is active`）；**命令行编译前先确认没有 UnrealEditor.exe**。

### 工程结论（架构层面的决策，后续别推翻）

- `game/Source/` 下：`Solstice`（Runtime）+ `SolsticeEditor`（Editor）两个模块，两个 `.Target.cs` **必须在 `Source/` 下**（UE 5.8 只 glob `Source/*.Target.cs`）。
- **删除了 `SolsticeSim.Target.cs` 与 `SolsticeSim` 模块计划**：`Solstice` 目标本身就无编辑器依赖，再加一个完全相同的 Game 目标只会让人困惑。无头回归改用 `SolsticeEditor` 的 `SolsticeBench` Commandlet。真正的零引擎依赖 Sim 模块留到 M1 存档需要时再做。
- **`SolsticeEditor` 的 `LoadingPhase` 必须是 `Default`**：`-run=XxxCommandlet` 的类解析在 `LaunchEngineLoop.cpp:3931`，早于 `PostEngineInit` 模块加载（`4861`）。写成 `PostEngineInit` 会报 `looked like a commandlet, but we could not find the class`。`-game` 下 `GIsEditor` 为假，Editor 模块仍不会加载（`ModuleDescriptor.cpp:730`），所以不影响发行路径。
- **跨 DLL 的公共类型必须标 `SOLSTICE_API`**：`UnrealEditor-Solstice.dll` 与 `-SolsticeEditor.dll` 是两个 DLL。踩过两次（`FPaperMaterials`；`FSimKernel`/`FDataLoader`/`FTile`/`FWorldConfig`/`FSkyState`/`FCatalog`/`FLoadedContent`）。排查：`dumpbin -symbols`（Git Bash 下必须短横线，`/symbols` 会被路径转换吃掉）。
- **静态持有 UObject 必须 `AddToRoot()`**：`FPaperMaterials` 缓存的 MID 在关卡加载时被 GC 回收，之后解引用崩 `EXCEPTION_ACCESS_VIOLATION reading 0xffffffffffffffff`。
- **无头日志里看不到 `LogTemp`**，且只加 `-stdout` 会丢尾部 → 定义了 `LogSolstice`，并一律加 `-abslog=<路径>` 读日志。
