## 第四程：UE 编辑器界面答疑 + "为何必须 Play 才看得到世界"

> 用户问："我为啥 play 才能看到项目。刚进去是全黑啊"（附 UE 编辑器截图）

**已核实的机制结论（经代码逐行确认，非推测）**：

- **根因**：世界不是关卡资产，是**运行时生成**的。`ASolsticeGameMode::StartPlay()`（`SolsticeGameMode.cpp:19-32`）
  才 `SpawnActor<ASolsticeRealm>`；而 `StartPlay()` 只在世界 `BeginPlay` 时被调，**编辑器视口里的 Editor World 从不 BeginPlay**
  → Realm 从未诞生。点 Play 时 UE 会**新建一个 PIE World**，在那里实例化 `GlobalDefaultGameMode`
  （`DefaultEngine.ini:12` = `/Script/Solstice.SolsticeGameMode`）+ Controller + Pawn（`ASolsticeObserver`）。
- **"纯黑"而非"一块空地"的第二层原因**：**所有的光都挂在 Realm 身上**——`SunLight`(DirectionalLight、
  只提供光**方向**，材质是 unlit 自己算硬色阶)、`SkyLight`、`Fog`、`PostProcess` 全是 `ASolsticeRealm`
  的构造组件（`SolsticeRealmActor.cpp:65/74/79/91`）。Realm 不存在 → 一盏灯都没有；空关卡自带的
  `SkyAtmosphere` 又被 `DefaultEngine.ini:39` 的 `r.SupportSkyAtmosphere=False` 废掉，`:25` 关了自动曝光
  → 无几何 + 无光源 + 无环境光 + 无曝光补偿 = 必然黑屏。
- **几何同样运行时生成**：`BeginPlay()`（`SolsticeRealmActor.cpp:124-164`）`NewObject<UProceduralMeshComponent>`
  建 chunk，`Tick()` 里 `Gen::BuildChunk` 逐块重建；`M_Paper`/`M_Ink` 由编辑器模块
  `SolsticePaperMaterialBuilder` 生成。Content 目录几乎空是故意的。
- **设计意图（三处写死）**：`DefaultEngine.ini:3-6` 注释（deliberately no level content）、
  `SolsticeEditor.cpp:13-15`（editor launch should not have side effects，故意不在启动时生成）、
  `STRUCTURE.md §0`（Content 里一切可从种子 + 生成器 + 契约重建）。
- **易被误解的细节**：编辑器下 `USolsticeGameInstance::Init()` **确实会执行**
  （`SolsticeGameInstance.cpp:13-55` 加载卡牌/物种/预设 + 初始化 Sim 内核），所以日志先出 `realm ... ready`
  再黑屏——**数据在内存里，只是没人把它变成画面**。

**未改动任何文件**。已向用户给出三条可选路线（不改就用 Play / 只调 PIE 播放设置 / 加编辑器内预览 Realm

### 结构性结论（踩过的坑，按重要性排）
- **「全是山」的真因不是高度太高，是面积分布**。改为**按面积分位重标**（`qTab`→`hTab` 钉 6 个锚点），
  `w.mountain` 直接控制「多少面积是高起来的那部分」。但分段线性在锚点处斜率突变，
  会留下 5 道「台阶肩」→ 混入 28% 全局平滑曲线才消掉。
- **`span = max(1e-9, ...)` 是台阶机的根源**：raw 高度分布有大量等值块时，
  分段重标退化成阶跃函数，一整片平原被映射到同一高度 + 中间一刀垂直崖。
- **省界混合必须用 3 个省**，2 个在三省交汇处必然留缝。
- **每个省都需要「骨架」**：内陆抬升 `intRise·(1-df)²` + 整体倾斜 `tiltA·(nx·cos+nz·sin)`。
  缺这两项，十几个省各自鼓成一坨 = 一盘盆景；有了才有「一块大陆」。
- **凸度限幅削不了「刀」**（两格宽三十米高的薄墙凸度并不大）。必须加**热力侵蚀**
  （四邻落差 > talus 就按 0.26 转移，8 遍、talus=2.1 cell），刀才会塌成崖、崖塌成坡。
- **台地/方山/丹霞必须「块状孤立」**：先用低频 fbm 取阈值做 mask，只有过了阈值的区域才抬起来，
  其余面积老实做平原。否则一个台地省 = 一整块被切了两刀的蛋糕。
- **喀斯特峰林不能用脊状噪声**：脊状噪声抬起来的是脊线，一排并列的脊 = 一副鱼骨（白色尖牙）。
  要用中等频率 fbm 取阈值得到孤立团块，再 `pow(t, 0.78)` 把顶压圆。
- **海峡/海湾**：贯通全世界的直槽 = 拿钢笔划两道线；沿走向收口 = 内陆直长湖。
  正解是**单侧半平面 + 从海岸往里渐浅**（`tpr = smoothstep(0.06,0.34,alongS)`），
  它一定是和外部海连通的湾。
- **海洋占比必须闭环**：`calibrateLand` 只按轮廓场反推 landR，不知道地形真正在哪儿沉下去，
  目标 20% 实际 40%。要在 `buildTerrain` 之后量出真实海域面积，按 `sqrt(want/have)` 修 landR 再重建
  （最多 2 次，误差 >1.2% 才继续）。实 now 目标/实际能对上 1 个点内。
- **尺度是比例问题**：R=220 时世界 440 m 见方却叫「大陆」，峰高 0.51R=112 m = 世界宽度的 1/4，
  这是「盘子上的石头」。改 R=520（1.04 km）、`hTab` 峰 0.30R（156 m）、树 0.044~0.084R。
- **树线要按真实峰高**算（`h/(peakR·1.02)`），写死 0.55R 会让山顶永远 u≈0.93 → 整条山脉寸草不生。
- **树木坡度上限 0.85 ≈ 40°** 太严，山坡全光板白；抬到 1.30（≈52°）才有林线。
- **岩浆**：`sigma = rad·0.17` 的环宽比火口半径还大，整锥发光像一块烧红的炭。收到 `rad·0.10` + 内侧 gating。
- **低频色调斑块**用单八度值噪声会在 30 m 尺度露出方格 → 改两八度、幅度减半。
- **UI 参数**：新增「地貌省数」滑块（走 reseed 路径 `PROVN`，不是覆盖字段）、
  世界半径 260~1400 m、直径/最高点/峰径比三个读数。

### 仍未解决（下一轮）
- 近景地面：低多边形大三角 + 纯色草皮，缺草/灌木/碎石层，是「模型很差」的主因。
- 山体仍偏「橡皮泥」：远景色调平、缺岩层与植被的层级关系。

## world-model.html 第三轮：从「观赏原型」改成「种子生成器」

用户改口了定位：**这个 html 是给游戏做种子生成器的参考实现，游戏端要直接调它拿数据**。
所以本轮的重点不再是画面，而是「一个字符串 → 一个世界 → 一份 JSON」。

### 结构性结论（按价值排）
- **「世界边缘一圈土台」的真身是裙边**：`tops[i] = Math.max(rh, 水位 + 0.0015R)`
  把所有裙边顶都不管三七二十一抬到水面以上 0.8 m，于是整圈露一条土带。
  改成 `tops[i] = rh` 之后，该沉到水里的自己沉下去，只在真有海岸崖处露出来。
- **水面必须是圆的**：地形片元有 `if (length(vW.xz) > uRCut) discard`（uRCut = 0.9945R），
  地形本体是个**圆盘**。水面做方形会在四角多出四块没有东西托住的水，顶视是"方盘浮空"。
- **面积统计口径必须和 calibrateLand 一致**。原来 `P.allCells` 数整个方形网格（含四角 r>1.4 的深海），
  分母被四角稀释 → 目标 32% 海实际显示 20%，滑块读数永远对不上。现在都只数 r<0.985 的圆盘。
- **极坐标谐波做不出半岛**，只能做"波浪边"。真实大陆有一条主伸方向（印度次大陆/佛罗里达/堪察加），
  要另加一条 `cos^4(θ-penA)` 窗把半径局部拉长 14~34%。用 cos^6 会变成尖角（像被拽出去一把）。
- **省数从 13~16 砍到 5~8，省池从 9~11 砍到 5~6**。用户原话：「没必要每次都有一大堆不同的构造组成，
  不要为了构建而构建」。现在每个世界有一个「主场省」（池首、包络 0.88~1.12）占 40~60%，
  其余是镶边配角（包络 0.52~0.86）。真实的一小片地本来就是「一种为主 + 一两种镶边」。
- **气候 × 地貌合法性表（CLIM_OK）**：雨林不能有沙丘/雅丹/黄土/方山，寒漠不能有喀斯特/珊瑚礁。
  不合法的换成等价物并计数，面板上报「N 处地貌按气候替换」——让约束在 UI 上可见。
- **全局主风向 `w.windDir`**：雅丹垄槽、沙丘脊必须共用同一个风向，否则相邻两省垄槽垂直，一眼假。
- **种子码**：`XXXX-XXXX`，前 7 位 Crockford Base32 装 32 位种子（去掉 I/L/O/U），末位是前 7 位之和 mod 32。
  编解码已验证 1:1 可逆。小种子会产生前导 0（4242 → 0000-44JT），正常。
- **交接数据 = `worldData()`**：游戏端只要 `rollWorld(seed)` + `worldData()`，不用带渲染代码。
  JSON 里含 provinces（面积构成）/ resources（树石矿采样数）/ **spawns（出生点候选：低地+缓坡+近岸）**。

### UI 结论
- 五张卡：种子码 → 世界构成 → 交接数据 → 参数 → 视图。
  交接卡必须排第三，不然 1280×800 首屏看不到（用户就是为了它来的）。
- 删掉「雪覆盖」「省界混合」两个滑块（前者与气候重复，后者是渲染细节）。
- 机位格点 / 剖面收进 `<details>`，省 ~200px。

### 仍未做（下一轮候选，按性价比）
- **没有河流**。这是最大的结构性缺失：有了 D8 汇流，三角洲/绿洲/峡谷/冲积扇才立得住。
- 气候是整世界一个值，没有纬度带与距海梯度。
- 三角洲、珊瑚礁是"凭空"的地貌（没有河口、没有火山岛沉降），现实依据最弱。
- 近景植被仍均匀（step=3 网格 + 小抖动），没有成簇的林窗。

## 续：河网/湖泊落地 + 沙漠着色 + 三处"假参数"清理

### 湖泊从"算出来"到"画出来"
- `buildRivers` 早就在算 `LAKEW`（优先级洪泛填高 > 2.6 m 的洼地），但 **从来没有几何**。
  在 `buildRiverMesh` 里给每个湖格补一张八边形水面片（1 心 + 8 边，
  36 float / 24 idx），整块湖按 4 邻接连通块聚成一片、共用**一个**水位
  （块内最高溢出高度 - 0.05 m），否则每格各用各的 hf，水面高低不齐像水洼。
- 半径抖动必须留余量：格距 1 格，两个多边形半径之和 < 1 格就漏。
  上一版抖到 0.44 格 → 整片湖变麻点，从孔里能看见水下的绿坡。取 0.72~0.88。
- 连通块 < 240 格不画（≈2.9 ha）。1.2 m / 110 格那版每张图 5~8 个湖，太假。

### 三处"顶到上限"的假参数（顶到上限 = 约束没在筛）
- 三角洲：判据从 `acc > 2.4×thr` 改成「和本世界最大河口比」`acc ≥ 0.62×maxQ`
  且 `acc ≥ 6×thr`，上限 5 → 3。现在实测 0~3 个，不再是每张图固定 5 个。
- 湖泊：0~3 个（之前 4~8）。
- 这两个是「不要为了构建而构建」的直接产物——随机性要靠判据自然收敛，不能靠掷骰子。

### 沙漠看起来是橄榄绿（知识—现实缺口）
探针量出沙漠世界陆地平均湿度 **0.21**（不是 0.10），而干度权重写的是
`1 - m*2` → 只有 0.58，绿底压得住沙色。改成平滑窗 `1 - smoothstep(0.10, 0.62, m)`，
m=0.21 给到 0.72；同时沙漠土色 0.726→0.782。现在沙漠真的发沙黄。
**同时删掉 `min(1, 可植树度*1.15)` 这道门**——它在沙漠里本来就接近 0，
最该变沙的地方反而一点沙都不上，纯属自己屏蔽自己；裸岩已有 `1-rock*0.88` 挡。

### 水面像撒了白糖（像素尺度错配）
`RIV_FS` 的法线扰动频率是 1.6 次/米，而世界 1 km 宽、屏幕上一米不到一个像素 →
每个像素拿到独立随机法线，高光变成椒盐噪点。降到 0.26 次/米、指数 52→24、增益 0.34→0.20。
（`WAT_FS` 的海面 sparkle 是同类问题，暂未动。）

### 树站在湖里 / 树被横向拉宽
- 只在 (i,j) 上判 `LAKEW` 不够：树是按 ±1.7 格的抖动落位的，
  湖外两格的树会一头栽进水里。**必须在落点 (fx,fz) 上再判一次**，且按 3×3 邻域。
- 树宽原本 `th*0.56`，而贴图是 192×384（宽高比 0.5）→ 横向拉伸 12%。
  改 `th*0.50`；高度分布改 `0.034 + 0.056*hash^1.6`（多数中小树、偶有高过林冠）。

### 工具坑：headless Edge 会缓存 file:// 页面
`_shot.py` 原本固定写 `tmp/_shot.html` 再截图，于是**改了代码但截图不变**，
排查河湖噪点时被这个假象带偏了好几轮。现在每次写唯一文件名 + `&_=<tag>` 破缓存。
**这条要记住：以后任何 headless 截图脚本都别复用同一个临时路径。**

## 续二：阴影半边暗的根因 + 生态层（温度/有效湿度/树线/河源）

### 「一半大陆和海洋发暗」= 阴影贴图 v 轴采反了
地形与水面两个片元着色器都写 `st = vec2(lc.x, 1.0 - lc.y)`。深度图是从 FBO 渲的，
纹理第 0 行就是 FBO 底行，**与 NDC 的 y 同向，不能翻**。翻了之后每个点采到的是
「关于光轴镜像那点」的深度，两侧深度差随位置**线性**变化 → 一条**直线**把世界劈成明暗两半。
去掉翻转换行后，`occl` 在开阔地形上恒为 0，只在真实背光处非零。
- 顺带把固定深度偏移换成**斜率缩放**：`bias ≈ texelSize·tan(掠射角)`。
  黄昏太阳高度 11° 时每 texel 深度差约 4 m，固定 0.22 m 会整片坡面自遮蔽（脏斑）。

### 生态层（new）：Whittaker × Körner
- **温度**：`t = P.temp·(1-0.55·h/peak)`，山脚到山顶按直减率降。
- **有效湿度** `EM = 湿度 / (0.32 + 0.92·t)`（降水 ÷ 潜在蒸散）。这一条让
  「同样下雨、冷热不同植被不同」成立——苔原 EM≈1 却仍是苔原，因为温度不够。
- **植被带**：`warm = smoothstep(0.10,0.42,t)`，`wett = smoothstep(0.34,0.66,EM)`，
  颜色 = 母质 → 裸土(冷∪干) → 绿(暖×湿)，统计出五档（冰雪/苔原/荒漠/草原/森林）。
- **树线** `uTL = (P.temp-0.10)/0.55`，再被雪线压到 0.92 倍。
  依据：全球高山/极地树线收敛于生长季均温 **6.4 ℃**（Körner & Paulsen 2014, Alpine Botany 124:1–12）。
  实测：苔原世界树线 15 m、寒漠 0 m、温带 86~114 m、雨林到顶。
- **地形雨/雨影**：顺风 7 格取高差，迎风增湿、背风变干，再按均值回正（只重分配、不改总量）。
  振幅按 `0.34+0.66·P.wet` 缩放，否则沙漠会被凭空造出湿润带。

### 河流三处修正
1. **沟头判据**改成坡度-汇水面积 `q·S² ≥ 1`（Montgomery & Dietrich 1992, WRR），
   平原 `S` 下限 0.10。再**顺流传播**（上游成河则下游必是河）——少了这步河网碎成一节一节
   （实测 3.45 km → 0.96 km）。
2. **河源分类**：沟头按高程/贴湖分成 冰川雪水 / 湖泊出流 / 山地泉 / 坡面汇流，
   写进 `rivers.sources` 与 `rivers.heads`。
3. **河岸带宽随流量**：多源 BFS 求「离最近河格几格 + 那条河的 q」，
   `W = 1.6 + 2.2·√min(q,6)` 格（≈9~17 m）。原实现是 ±2 格箱式模糊 = **±5 m**，
   画面上就是一根线，「河从旱地里硬切过去」的观感来自这里。BFS 也顺手给出 `RIVNEAR`。

### 生态↔颜色的解耦（PROVT 延后上色）
第一遍只存 `BASEC(母质) / VEGPOT / DRYPOT`，等高度定稿（温度要按高程）和河网跑完
（河岸湿度）再统一上色。三角洲改成写 `PROVD` 权重，颜色在最后混。

### 四个「数值把自己骗了」的 bug（都是量出来的，不是看出来的）
- 地形雨回正写成 `(sum0-sum1)/n` → 总量**翻倍**，沙漠世界平均湿度 0.10→0.25。
- 湿度噪声振幅固定 ×1.70：0.10 的沙漠大量撞 0 下限、0.92 的雨林撞上限，
  两头都被**推向中间**（沙漠变湿、雨林变干）。改为 `2.2·min(wet,1-wet)` 封顶。
- `PROV_TREEK` 把「崖壁陡」当成「整块地贫瘠」（方山 0.13、丹霞 0.18）→
  温带森林世界里 43% 的台地是光秃红土。表只管基质，崖壁交给坡度项。
- `PROV_ROCK[mesa]=0.66` 让台地**顶面**也铺浅灰岩色，远看像积雪、与真雪线撞车 → 0.30。

### 现状
- 8 个种子：870~1020 ms，无 ERR；树线/植被带/河源读数都连续、可交接。
- 新增导出：`ecology{mean_temp, tree_line_m, snow_line_m, wind_azimuth_deg, biomes[]}`、
  `rivers{sources, heads}`；面板新增「树线 / 雪线」「植被带」两行。

## 续三：UE5 能否提供「更完善的生态方案」——本机 5.8.3 实测结论

用户问要不要改用虚幻引擎确保生态完善。结论：**引擎不提供生态算法，只提供容器**。
以下为本机引擎源码/插件目录实测（不是凭印象）：

| 能力 | 本机 5.8.3 实况 |
|---|---|
| 地形侵蚀 | **只有笔刷**：`LandscapeEditorObject.h` 里 `Erosion`（热力，带 `bErosionUseLayerHardness`）与 `HydraErosion`（`RainAmount` / `SedimentCapacity` / `HErodeIterationNum` 上限 300 / `RainDistMode`）。没有「对整张地形跑物理迭代」的 API/管线 |
| 植被撒点 | `PCG` 插件 **1.0**（5.8 已转正）+ `PCGSurfaceSampler` / `PCGSplineSampler` / `PCGDensityFilter` |
| 生态工具 | `Experimental/PCGBiomeCore` + `PCGBiomeSample`（0.2，实验，纯 Content/蓝图资产：BiomeDefinitions / BiomeGenerators） |
| 水文 | `Water`：`WaterBodyRiverActor`（样条河）、`BakedShallowWaterSimulationComponent`、`JumpFloodComponent2D`（岸距场，与我用的多源 BFS 同思路） |
| 外部数据互操作 | `PCGExternalDataInterop` 只有 Alembic，**没有** JSON/CSV 直读节点 |
| 外部工具 | Houdini `Heightfield Erode`、Gaea Erosion 才有真正的泥沙输运侵蚀 |

四条「生态相辅相成」的差距（与引擎无关，靠算法）：
1. 侵蚀→土壤（深度/养分/成土年龄）→ 植被 的真实驱动链（三方全缺）
2. 植被→侵蚀速率反馈（UE 笔刷的 `bErosionUseLayerHardness` 证明工业界就是这么干的）
3. 干扰机制（火烧/风倒/滑坡）→ 林窗与嵌块
4. 干旱区双稳态与滞回（Scheffer 2001 Nature 413:591；Rietkerk 2004 Science 305:1926）——线性插值做不出阈值

**定位判断**：本原型是「种子生成器 + 数据源」，UE 是下游消费者，不是替代品。
真正的缺口是**导出面**：16-bit 高度图 / 湿度·温度·可生长度·离河距离四张权重图 / 河网折线 / 树木实例表。

## 续四：转 UE 管线的选型结论（网络核查 + 本机复核）

用户拍板「全面转 UE 管线」，要求给出更新后的技术栈。核查结果：

**UE 5.8 三件关键新东西（本机已确认存在）**
- `Plugins/Experimental/MeshTerrainMode`（1.0，Experimental）：真 3D 网格地形，官方称支持浮岛/悬崖/

- `Plugins/Experimental/ProceduralVegetationEditor`（**1.0**）：节点图直接生成 Nanite 植被，官方称树木

  21+ 起分「带 PCG 支持 / 不带」两个插件版本。**Windows 必须装到项目目录**，装引擎目录会出问题。

**关键参考文献（闭环的参考实现）**
Nilles, Günther & Müller, *Oasis: A Real-Time Hydraulic and Aeolian Erosion Simulation with Dynamic
Vegetation*, GRAPP 2025, pp.39–52, DOI `10.5220/0013112100003912`。分层高度场（基岩/土壤/沙）+ 统一湿度模型
统一水力与风力侵蚀 + 植被栅格成密度图反向抑制侵蚀 + 生态位与竞争矩阵 + 风传播。2048² + 200 万株实时。
→ 结论：生态闭环应**离线伪时间迭代 100~200 步**烘成贴图，不在运行时模拟；1 km@1 m = 100 万格，GPU 够用。

5.8 是 UE5 最后一版，UE6 在即；Mesh Terrain / PVE / PCGBiome 全 Experimental（社区反馈 Mesh Terrain
撤销栈在 >200 万面时卡顿、Sculpt 投影模式偶发异常）。核心游戏路径不要押在实验功能上。

**定位不变**：HTML 原型 = 气候与植被判据计算器 + 种子调试台 + 贴图/JSON 导出器；UE = 消费者。

## 续五：原型落地「动态生态内核」+ 商业件全免费替代

### 做了什么（studio/previews/world-model.html，4947 → 6100+ 行）

新增第 11.5 节「动态生态模拟内核」，是一张 **256² 世界状态栅格**（格距 4.06 m）：

- 通道：V 植被 / W 土壤水 / B 燃料 / F 火 / C 云 / R 降水 / N 养分 /
  A 雪 / E 侵蚀 / S 河道蓄水 / M 稳态位（草原=0 森林=1），外加只读的 BURN。
- 分频：火 1 min、天气 2 min、水 2 min（与天气**错开**，避免同一帧两个 65k 全扫）、
  慢过程 20 min、对流脉冲 60 min。
- 火：Huygens 离散化，`p = rate·dt·dirW/dist`，方向权重 = 风 + 上坡。
  燃料按**比例**烧（`b·0.52/min`）而不是固定量——写成固定量会导致「火比草先烧完」，
  永远烧不出去（踩过）。
- 天气：`qsup = 0.18 + 0.62·V + 0.20·W + 0.22·near`（陆地）/1.15（海），
  `tgt = qsup·0.50 + conv·0.95`，`conv` 来自火 + 迎风坡 + 64² 对流脉冲场。
  降水阈值 0.62，`R = (C-thr)·2.2`。
- 水：冠层截留 → 下渗 → 蒸散 → 超渗产流 → 重力排水（田间持水量按 EM 给
  0.42~0.76）→ D8 拓扑序汇流（`relK = 1-exp(-0.05·dt)` 提出循环省 6.5 万次 exp）。
- 慢过程：双稳态（Pausas & Bond 2020）+ 养分 + 侵蚀 + 雪 + 烧痕褪色。
- 三维叠加：把 F/BURN/雪 打包成 256² RGBA 纹理，地形 FS 采样，
  火用 `pow(simF,0.45)` 提亮（平方会把 0.05~0.3 的真实火强压成看不见）。

### 八个必须记住的标定坑

1. **土壤水**：1 m 土层饱和→凋萎 ≈ 85 mm 有效水，PET 5 mm/天 → 17 天。
   `pet = 2.3e-5/min`、`infil·0.0025·dt`。这两个系数给大 4 倍，W 一路涨到 1，
   整张图变沼泽。
2. **水汽基线**：陆地 qsup 基线给 0.13 时，陆地云量永远撞不到降水阈值 →
   一年不下雨 → 植被全枯 → **干旱自锁**。必须 ≥0.45 才有正常降水。
3. **降水阈值**：0.44 时全世界每步都在下雨（年降水折合上万毫米）。要 0.62。
4. **天气不能是匀的**：`tgt` 收敛到同一个数会让全世界一起下/一起不下。
   加了 64² 滚动噪声场（对流脉冲）才有「这团在下、隔壁晴」。
5. **双稳态不能拿「当前燃料」当门槛**：草原态燃料上限只有森林的 1/6，
   `toForest` 里带 `b>0.26` 会让火烧过的林子**永远回不来**。
6. **食草量级**：0.014/慢步 是「五天啃光草原」。要 0.0015，且森林态按
   `(1-0.7·M)` 打折（牛羊进不去林冠）。
7. **水分响应要非线性**：`((W-0.15)/0.55)^1.6`。线性的话沙漠拿到 0.5 承载量。
8. **火的蔓延与燃烧必须匹配**：rate 0.92 m/min 时火线一分钟走 2 m，而燃料
   14 分钟烧完 → 火自灭，永远烧不开。rate 提到 3.9（接近栅格上限 4 m/min）。

## 续七：树接上状态栅格 + 六个「看不见」的生态 bug + 面板文案重做

用户三问：火烧了树没影响？多次测试了吗？还有哪些没发现的生态漏洞？

### 一、树之前完全没接模拟（用户说对了）

`treeSets` 是 buildTrees() 一次性生成的静态实例，`S_V` / `S_BURN` / `S_F` 与它无关。
修法：`TRE_VS` 里直接采样状态栅格（WebGL2 顶点纹理提取），`TRE_FS` 用 varying 拿结果：

- `hK = 0.30 + 0.70*smoothstep(0.30, 0.78, vig)`，再乘 `(1 - 0.16*brn)` → 烧过的树变矮成焦桩
- 每棵树 `rnd = fract(sin(dot(aCenter.xz, vec2(12.9898,78.233)))*43758.5453)`
- `deadK = smoothstep(0.42,0.90,brn) * (1 - smoothstep(0.26,0.58,vig))`，`if (deadK*0.55 > rnd) discard`
  → 烧透且没恢复的树按各自阈值消失（保留约 45% 焦桩；**不能用逐格统一阈值**，
  否则整片林在同一帧整齐消失）
- 燃烧中：`col = mix(col, vec3(1.58,0.62,0.14), fq*burnUp)` + 自发光
- 烧后：整体拉向炭色 `vec3(0.062,0.055,0.050)`

### 二、六个隐蔽 bug（都是"没有报错、只是不对"）

1. **两张纹理只设了后一张的过滤参数**。默认 MIN_FILTER 是 NEAREST_MIPMAP_LINEAR，
   无 mipmap → 纹理不完整 → 采样恒返回 0。表现：火不亮、树不焦、地不湿，零报错。
   一张纹理时不会出现，加到第二张才出现。
2. **土壤水 200 分钟后全图拉平**：中位数 0.758、最大值 0.768。降水在每一格都在下
   （云量中位 0.71 > 阈值 0.62），补水把气候差异抹掉了。修：加深层水库锚定
   `S_W += ((0.10+0.85*EM0) - S_W) * 0.020 * dK`。
3. **坡面流与河道蓄水挤在同一个 S_S**：中位数 1.16、99% 分位 4.7（= 每格 4 米深的水）。
   修：用 `S_RIV` 河网掩膜——河道格累积、坡面格每步排掉 58%。
4. **火烧后没有斥水性**：`infil *= (1 - 0.62*S_BURN)`。这是火→水最硬的一条耦合，
   没有它火对水文零影响（Santín & Doerr 2016）。
5. **积雪不降温**：`tN = S_TP0 + tOff - 0.045*S_A`，闭合「雪→温度→融雪→河流」。
6. **植被整片集体复活**：加种源限制 `seedK`，取四邻域 V 的最大值。
   **只对 `S_BURN > 0.10` 的格子生效**——否则沙漠会陷入
   「我稀疏→邻居也稀疏→我长不起来」的自锁（实测沙漠 V 掉到 0.02）。

### 三、三个标定值

- 植被恢复 `gr = 0.030 → 0.008`（时间常数 11 小时 → 2.2 天）。树高跟着 V 走，

## 续八 · 边缘重做 / 随机性 / 河网（用户提的四问）

### 一、边缘为什么"像个培养皿"

顶视那张图里，陆地外面是一圈**惨白的环** —— 那不是海，是 `edgeFade`：
水面片元从 `0.84R` 就开始往雾色混，而陆地边缘在 `0.6~0.75R`，于是
「近岸 → 盘边」整条都罩着雾色，加上水盘正好在 `0.998R` 结束，
读出来就是「玻璃盘上摆了一块地」。

改法（三处，缺一不可）：
1. `buildWaterMesh`：水盘半径 `0.998R → 12R`（segR 34→28、径向幂 0.88→2.40）。
   地形仍在 `0.9975R` 裁圆，但外面是**开阔海**，永远看不到盘的边。
2. 水面着色器：去掉 `edgeFade`，改成**按距离**的雾
   `1-exp(-pow(max(d-0.75R,0)*uFogK*2.10,1.70))`。
   按半径雾（`smoothstep(1.0,1.95,rEdge)`）俯视行、压低视角就露馅：
   脚边几米的水也被当远海染灰，海变成两块分界线笔直的板。
3. 地形之外没有海床，`dep` 直接换 `uDeep*2.4`，
   否则采样被 CLAMP_TO_EDGE 钉死，拉出放射状条纹。
4. 深海色 `mix(uWat[2], uWat[1], 0.30)` 提亮：原色 RGB(13,64,101) 在掠射角下像塑料。

### 二、随机"总是几套一样"——量出来的三个真因

不是随机数坏了。1200 个种子实测：原型 192~206/200、气候 176~215/200，分布是均匀的。
真因是**每类内部的组合空间太小**：
- 省数只有 4~8，且**主场写死 pool[0]** → 同一原型打开就是那片高地
- 离岸岛只给群岛/火山两个原型（80 个种子里 34 个 `isle=0`）→ 永远是「一块地浮在水上」
- 6 个气候各自绑死配色/树种/雾 → 同气候两个世界只看颜色分不出

改：省数 → 9~13（间距 0.235→0.185）；主场 40% 概率取 `pool[1]`（6 原型 → 12 主调）；
离岸岛所有原型 46% 概率；谐波幅度去掉 `/(1+hh*0.7)` 的强衰减；
气候 `wet/temp/forest` 各加 ±14% 抖动（不改定性）。
复测 80 种子：省数 6~13（med 10.5）、66% 有离岸岛、33/36 个 arch×clim 组合都出现过。

### 三、河网：mouths 8~14、forks 0~5 的成因链

实测（5 种子）：`heads 10~15`、`forks 0~5`、`mouths 8~14`、`sinuosity 1.03~1.16`。
即「十几条各自入海的直线沟」。三层原因，逐层修：

1. **地形是穹顶** → 水沿半径放射状流走，两条相邻沟永远不会汇合。
   加**造山带**（`orH/orX/orZ/orW`，沿随机轴的高斯脊 × 脊状噪声 grid 项 `nf.rg`），
   削弱 `intRise`（0.032~0.062 → 0.016~0.036）、加大 `tiltA`（0.024~0.050 → 0.040~0.076）。
2. **没有侵蚀反馈** → D8 只是在噪声上画线。加 **stream power 迭代 2 轮**：
   `dh = 2.2·(q/qref)^0.45·S^0.85`，且
   - 近岸 12 m 内不下切（否则海平面附近凭空多一圈湖）
   - `dh ≤ 0.70·(hf−hf[下游])`（不能把坡刻反，否则 order 失效）
   - 单轮上限 `0.012R`
   侵蚀量 `INC` 要**回写到 hgt**（判据改成 `dv>0.0002 || INC>0`），否则河间地没被削，谷坡刻不出来。
3. **填洼判据只看深度不看面积** → 一个世界 4000~7600 格被判成湖（≈15% 陆地），
   而且 `inLake3()` 用同一份 LAKEW，于是那 15% 的地**长不了树**（这才是"生态漏洞"的真身）。
   修：`LAKE_DEP 2.6→3.6`、`LAKE_MIN=150` 连通域过滤，渲染阈值一起改成 `LAKE_MIN`；
   并且**填洼跑两遍**（`flood()` 封成函数）：侵蚀刻深出口后再填一次，
   被刻穿的盆地自动变干 —— 湖泊占比 15% → 0~4.4%。

## 续九 · 河流根治 + 全屏海洋 + 视角锁定（用户提的三问）

### 一、河宽「不随流量变」——真正原因是上限，不是没接流量

`hwAt = cell·min(2.0, 0.46+0.50·√q)`。实测 q50 已经 3~5、q90 9~22，
所以**一半以上的河格在公式里就顶到 2.0 格（4.8 m 半宽）**。
用户看到的「所有河一样宽」来自这里，不是数据不足。

改成纯幂律（Leopold & Maddock 1953，w = a·Q^b，b≈0.5）并按格数封顶：
`cell·0.5·min(10, q^0.62)` → q=1 时 2.4 m、q=16 时 14 m、q=47 时 25 m。
同时河谷加宽半径 3 → 6 格（13 格 = 31 m）：**谷必须比水宽**，
否则干流的水面带会盖到岸上，像一条蓝布带浮在山上。

实测（6 种子）：半宽中位 2.3~2.9 m、90% 分位 4.3~8.3 m、最大 11~12 m。

### 二、河网碎成「一把刷子」——判据里的两处结构性错误

症状：`heads 14~24` 但 `mouths 34~165`，且前几名汇水面积**完全相同**。

**错误 1（真凶）：`sk0` 下限。** 原来是 `if (sk0 < 0.10) sk0 = 0.10;`
（后来放宽到 0.020，仍错）。下限一 clamp，S² 变常数，
判据退化成「只看 acc」，等于说「只要流域够大，多平都能成沟」。
于是填洼后每一片平地的 eps 斜面都被判成河道，D8 在上面是**平行梳齿**，
同时抵达海岸 → 一堆河口。

改成原始形式 `acc·cell·S² ≥ C`（C=120 m，Montgomery & Dietrich 1992），
**S 绝不设下限**。平原 S→0 就不产沟头，平原河段由「顺流传播」保住。

**错误 2：河谷下切穿海平面。** `maxDrop = 0.0135R` = 6.75 m，
比沿海低地本身还高，于是河道一路削到水下，出现「一段河沉在海底」。
链上每一格的下游都在水下，全部被记成一个入海口 —— 这才是 mouths 爆炸
的真正来源（不是河网真的碎）。修：`maxDrop = 0.006R`，
并且河床夹住 `hgt ≥ wlv+0.22`、水面夹住 `RIVW ≥ wlv+0.15`。

修完：`riv 516~1060 格`、`density 2.6~6.1 km/km²`（陆地面积口径）、`mouths 4~13`。

> **教训**：诊断脚本判「海」不能用 `HGT <= 0`，海平面是 `P.wl·R`。
> 这个误判让我一度以为有 128 个入海口，浪费了一整轮排查。

### 三、「整个屏幕都是海洋」（用户的方案）

**做法**：水盘半径 12R → 40R，并且**每帧把盘心平移到相机脚下**（`uSeaOff`）。
顶点数不变（192×28 环），但任何视角、任何 zoom 都不会看到盘的边。
径向幂律 2.40 → 1.90（40R 的小幂律会让外环间距拉到 20R，三角太肥）。
`far` 24R → 60R（12R 的水盘被远裁剪面切成一块「边界笔直的深蓝板」）。

**必须同时做的两件事**：
1. 深度采样边界改**切比雪夫距离** `max(|x|,|z|)/R`：地形是方形的，
   用半径会把四个角（1.414R）也当成「海床之外」。
2. `fogCol` 改用 `T.low`（地平线色），不是 `T.fog`：两者差 10%，
   天地之间就横着一条能看见的线。

### 四、删掉的两样东西（用户点名）

- **天空的 `uVoid` 兜底**（`mix(uVoid, col, smoothstep(0.02,0.30,y))`）：
  那是给「水面只到 1R」的旧模型擦屁股的，海铺满后就是屏幕底部一块矩形暗影。
- **水面采样阴影贴图**（`sm`，9 次纹理读取）：在湖里是加分项，
  在海面上读成「岛在水里的倒影」—— 颜色发蓝、同形、方向不对。

### 五、视角锁定

`pitch 35 → 22`，`yaw 315` 固定；删掉 8×4 的机位网格，换成三档缩放
（全貌 1.00 / 标准 0.70 / 局部 0.45），滚轮范围收紧到 0.42~1.25。
22° 的理由：35° 以上变成俯视地图、海缩成岛外一圈；12° 以下地平线进画面、
又回到「一堵水墙」；22° 是「一片海 + 一座岛」、顶部只留一条天色。

> zoom 语义是 `d = fitDist·zoom`，**数值越大越远**。
> 第一版档位写成 0.52/1.0/1.85，「局部」反而把岛缩成了芝麻。

### 六、导出补河网与湖面

- `rivers.polylines`：每点 `[x, z, 水面高, 半宽m, 流量0..1]`，
  由 `buildRiverMesh` 顺手存下（**已经走好、已经平滑**），抽稀到每 2 点取 1。
  6 种子实测 13~24 条折线、529~1084 点，整份 JSON 18~34 KB。
- `rivers.lakes.shapes`：每个湖 `{cx_m, cz_m, level_m, cells, bbox_m}`。
  用 bbox 而不是多边形 —— 这些湖只有几格到几十格，框更好落地。
- **湖判据不能写 `LAKEW[k] > 0`**：LAKEW 存的是绝对水位（米），
  海平面可以是负数。用 `!LAKEW[k]`。
- `density_m_per_km2` 原来除的是整个世界圆面积（含海），改除陆地面积。

### 七、测试

- 模拟回归 3 种子 × 2000 步：1.82~1.98 ms/步，NaN=0
- 河网体征 6 种子：`density 2583~6094 m/km²`、`mouths 4~13`
- 导出 10 种子：折线 13~24 条、点 529~1084、JSON 18~34 KB、湖 0~4 个

### 未做 / 已知

## 续十 · 大陆原型 / 海岸坡度 / 视角 14°

### 一、用户四点诉求里的比例问题（先算，再改）

| 量 | 当前值 | 真实对照（1 km 岛） | 判断 |
|---|---|---|---|
| 世界直径 | 1040 m（R=520） | — | 「一处山谷」的尺度 |
| 地形格 | 5.42 m（NT=192） | — | 偏粗，但够画河网 |
| 峰高 | 137~172 m | 100~300 m | 合理 |
| 树高 | 17.7~55 m（均 27） | 20~40 m | 合理 |
| 河宽 | 全宽 5.4~25 m | 3~30 m | 合理 |
| 湖 | 最大 3922 格 ≈ 340×340 m | 100~500 m | 合理 |

**结论：数值比例没错，错在「观感尺度」**——1 km 的世界里塞 14 个地貌省，
每省只有 200 m，加上海岸线碎，读出来就是「一堆小岛」。

### 二、新增「大陆」原型（arch 6）

`{ landR:[1.02,1.20], aspect:[0.94,1.12], sea:[0.16,0.26], relief:[0.86,1.08],
   harm:2, minN:12, maxN:16, kink:1.28 }`，省份池 `[plain, plain, hill, mtn, plateau, plain]`。
`arch === 6` 时 `w.isleAmt = 0`（不要离岸岛链）。

实测陆地占比：**0.66~0.75**（其余原型 0.43~0.71，岛屿 0.17~0.40）。

### 三、海岸坡度：三个连环 bug

用户说「边缘像一块切糕」。查剖面（沿 +x 采样）：
`43.4 → 39.8 → −30.8`，**最后 26 m 降 70 m**。

1. **`RIM_A/RIM_B = 0.940/0.982`**：这圈「强制压海带」只有 22 m 宽却要降 90 m。
   它是为了「别让陆地顶到裁切边界」加的，但 `landField` 的 df 过渡带早就保证了边缘是海。
   → 推到 `0.975/0.9965`，只在最后 1% 兜底。
2. **df 过渡带太窄**：`smoothstep(0.900,1.060)` 只有 0.16（70 m）。
   → `0.700/1.140`（213 m），海岸坡度 62° → 35°。
3. **`coastFall` 方向写反了**：第一版 `0.30 + 0.70*smoothstep(0.35,1.06,df)`，
   df=1（海岸）时是 0.99、df=1.06（海里）才降到 0.3 —— 等于没衰减。
   → 改成 `1.0 - 0.70*smoothstep(0.45,1.00,df)`：内陆 1.0、海岸 0.30。
   **这条才是「山不许直接切进海里」的关键。**

### 四、`calibrateLand` 的口径 bug

它用 `rawHeight() <= 0` 算海，而 rawHeight 里乘了 rimMask。
rim 带占 25% 面积 → **无论 landR 多大都有 25% 的海** → 二分把 landR 一路推到边界，
陆地顶到裁切处，整圈变垂直崖。
→ 给 `rawHeight(nx,nz,w,pwIn,noRim)` 加参数，`calibrateLand` 传 `noRim=true`。

### 五、视角 22° → 14°

用户原话「拉远显得怪、不像在海上」。14° 时海占下半、陆地横在中景、天空占上面 1/3，
是「站在船上望大陆」。配合 40R 水面 + 60R 远裁剪，四边都是水。

### 六、调试接口修复

`__wm.rebuild(sd, a, c)` 之前忽略 a/c（只传 seed），导致「所有原型测出来一模一样」。
→ `regenerate(newSeed, archOv, climOv)` 透传。

### 未做

- **湖岸线仍是方块**（填洼面绝对水平 + 八边形半径不够），需要 Marching Squares
- **天气只有云/雨云色，没有雨丝、雪、雷电落地的效果**
- 世界仍是 1 km 尺度；要「真大陆」需 R×10 且 NT 提高，性能会翻几倍

## 续十三 · 地表去噪 / 雾色归位 / 水盘铺远 / 俯角 9°

用户：「多分析问题多调整解决问题」。这轮不问了，按自己列的清单硬修。

### 一、地表「蒙泥」的真身：八层噪声叠加

岩石着色里有 `facet / strata / mes / grit / crk` 五层，每层乘 0.9~1.1；
再叠各地貌专属层（gr / crv / col6 / vj / bed / yv / rp）+ 矿脉。
每层只 ±10%，**叠起来就是满屏灰点**。

删掉 `grit`（碎石）与 `crk`（裂隙）两层，`mes` 0.080 → 0，
其余高频层强度减半。植被噪声频率 `pUV*0.62`（每格都在变）→ `pUV*0.12`（40 m 一块）。

### 二、海天硬边：雾色取错了天空的那一段

天空 shader 是 `mix(low, mid, smoothstep(0.03,0.34,y))`，
但 12~14° 俯角下地平线落在 `vUV.y ≈ 0.9`，**那里早就是 mid 了**，low 只占屏幕底部几像素。
而 `fogCol` 取的是 `T.low` → 海的尽头（米白）和天空底部（mid 青蓝）差一个色相
→ 横贯全屏一条米白带。

**改 `fogCol = T.mid`**。这是第二次栽在「雾色必须等于地平线处天空的实际颜色」上。

### 三、水盘 40R 不够，远裁剪 60R 也不够

pitch 降到 12° 后，水盘边缘进画面（露 clearColor）。`wR 40R → 110R`，`far 60R → 160R`。
深度精度：near 0.04R / far 160R，24 位够用。

### 四、海雾起点 0.75R → 2.2R

0.75R 意味着岛外一圈就开始雾化，整个中景是同一个蓝，海没有层次。
推到 2.2R：岛周围 0~2R 是本色海水（浅滩青绿→深水钴蓝），2R 外才融进天空色。

### 五、俯角 14° → 9°

14° 时天空只占 13%（一条缝）。9° 时天空 20%、海 45%、陆 35%。

### 六、沉浸 / 壁纸模式（上一轮加的，本轮沿用）

`body.imm` + `&imm=1`，全屏无 UI；沉浸时相机 `d *= 0.60`。

- **树还是贴图 billboard**，远景是「绿色小圆点」。要真低模几何（3~5 个纯色面 + 两档明暗），
  工作量在一轮以上。

## 续十四 · 参考 Tiny Glade（用户给了截图）

### 关键认知修正：Tiny Glade 不是「动漫风」

搜索（Digital Foundry / 官方更新日志）确认它的画风来自三样，**没有一样是 cel shading / 描边**：

1. **软件光线追踪的漫反射全局光照（RTGI）**：代理几何 + BVH + 1/4 分辨率采样 +
   球谐编码 + 后处理降噪。光线在墙、草、石之间反弹，所以「暖」和「柔」是算出来的，不是滤镜。
2. **移轴景深（tilt-shift DOF）**：DF 的原话是「把相机抬到远处俯视时，
   它看起来像一个真的微缩模型」。这是「摆件感」的直接来源。
3. **暖调 + 高调（high-key）**：米石、橙瓦、黄绿草，几乎没有纯黑。

另外它是**圆形 diorama 边界**：边界外是落差 + 风格化雾，相机 orbit-lock 锁在中心。

### 这轮改动

1. **加移轴景深**（POST_FS）：线性深度算 CoC，只模糊「比焦平面远 1.18 倍」的部分，
   10 tap 黄金角螺旋。`uFocus = CAM.dist`、`uDof = 1.5`。
2. **俯角 9° → 36°**：9° 平视时画面里只有「岛 + 一片纯蓝的海」，
   模糊纯蓝等于没模糊，而且没有近景层，读起来是航拍而不是摆件。
3. **温带森林草地提亮**：gA `[0.478,0.706,0.318]` → `[0.560,0.820,0.330]`，
   gB/gM 同步 +12~15% 明度，gH（暗部）保持深绿 —— 全亮会变塑料草坪。
4. 沉浸模式 `d *= 0.86`（0.60 时岛占满、看不到海）。

### 仍未解决的硬差距

- **RTGI 在 WebGL 原型里做不出来**。可行的近似是 SSAO（屏幕空间环境光遮蔽）：
  用已有的深度图算接触阴影，能把「物体之间没有光反弹」这个最伤真实感的问题补一半。
- **景深效果弱**：缺少近景物体（相机下方什么都没有），且远景是纯色海。
  Tiny Glade 的有效果是因为近处有草、远处有树。
- 树仍是贴图 billboard。

## 续十六 · 视角 16° / 海天线的真因（纹理不是颜色）

### 视角：36° → 22° → 16°

用户说「视角太高了」。关键约束：**FOV 是 35°，所以俯角必须 < 17.5°
画面上缘才会高过地平线**。22° 和 36° 时画面里根本没有天，只有岛 + 海。
16° 时上缘朝上 1.5°，海平线进画面，构图才是「天 / 海 / 岛」三层。

### 海天线：查了一晚，真因是「纹理突变」

三轮采样都显示**逐像素只差 1~3，完全平滑**，所以既不是色阶跳变，
也不是马赫带（改成线性插值后线还在）。

真正原因：**天空是纯色渐变，海面有波纹 `wn` 低频明暗**。
两者在雾里颜色完全一致（采样证明），但**纹理的突变**让眼睛读出一条边界。
人眼对「纹理密度」的突变比对亮度敏感得多。

修法：
```glsl
float wn = mix(0.5, wnRaw, 1.0 - smoothstep(uR*1.6, uR*5.0, dTex));
```
远处海面的 wn 拉回 0.5（= 乘 1.0，无明暗），和天空一样平。**线立刻消失。**

> 这条是整晚最有价值的发现：**渲染里「看得见一条线」不等于「颜色对不上」**。
> 纹理密度、曲率、运动矢量都能造出线。

### 天空改线性插值

两段 `smoothstep` 拼接在端点导数为 0、中段最陡，曲率突变会形成马赫带。
改成 `clamp((y-a)/b)` 线性，顺带修掉。

## 续十七 · 一次性收尾（陆架 / UI 文案 / 视角 16°）

### 一、岛「浮」在海面：海床剖面是线性的

`h = hl*coastFall*lm - (1-lm)*seaDepth` —— 水深随 lm 线性增加到 48 m，
所以岸外十几米就是深海，岛看起来像一块板浮在水上，边缘一圈亮青像描边。

改成 `- pow(1-lm, 1.85) * seaDepth`：**先慢后快**，造出大陆架。
lm=0.9 → 0.8 m；lm=0.5 → 13 m；lm=0 → 48 m。
浅滩带自然变宽变柔，水面着色的 `dep` 也平缓了。
同时 `shelf` 强度 0.20 → 0.10、`foam` 0.38 → 0.26。

### 二、UI 文案：从「复述参数名」改成「数值 → 效果」

## 续十九 · 景深也没生效（和礁石同一个症状）

把 `uDof` 从 1.5 提到 **5.0**，画面**逐像素不变**。说明 POST_FS 里那段 DOF 根本没执行。

嫌疑（按可能性排序）：
1. `dc < 0.99999` 的判断：`uD` 是深度纹理，如果它被读成 1.0（或者格式不是深度），整段被跳过

   `coc` 恒为 0（`clamp((zz - focus*1.18)/..., 0, 1)` → 负数 → 0）
3. uniform 名字没对上（`progPost.u.uDof` 为 undefined，`uniform1f` 静默失败）

**这三个都只能靠「在页面里读回 uniform 和中间值」确认，看图永远看不出来。**
