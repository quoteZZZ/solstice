# Solstice · 整体表现诊断（2026-11-04）

> 对象是 `650b351` 的原型。全部数字来自当场实测（无头探针 + 视口像素统计），
> 不是目测。问题编号 `P0-1`～`P2-5` 可回查。结论只写「哪里不行、为什么、先改哪个」，
> 规格不动，缺口落 STATUS。

---

## 0 结论

**机制骨架通了，两头没过关。**

能起世界、能活两年、能抽卡、四档包有价差、撤销有守卫——可玩性的**结构**是完整的。
但「看」和「上手」都还停在能跑的水平：画面是一块被均匀照明的灰绿板子（**73% 的像素挤在
0.2–0.4 亮度，0.5 以上只有 208 个像素**），开局把 **85%** 的卡设成不可用却只给两行字说明。

三个要命项：

1. **灰显系统在开局 30 秒内自我否决**——打完第一张土地，8/8 全亮。引导作用归零。
2. **4 张卡高亮说能打、落到格上被拒**。卡手感最强的一刀不是「没牌可打」，是「我照做了它还说不行」。
3. **画面没有任何亮部**。「造世界」的成就感没有视觉回馈——世界长出来了，但看起来没长。

## 1 画面质量

### 1.1 成本实测

| 项 | 实测 | 判断 |
|---|---|---|
| 可见格数 | 1307 | 四档包撑到的规模 |
| draw calls | **917** | 高 |
| geometries | **1674** | **大于格数** → 几何每格新建，零共享 |
| 三角数（视锥内） | 5548 | 低 |
| shader programs | 10 | 合理 |
| `R.sync` | **1.05 ms/帧** | CPU 侧主开销 |
| `marks.frame` | 0.00 ms | 正常 |
| `cam.frame` | 0.07 ms | 正常 |
| `faceCam` | 0.047 ms | 正常 |

**结论：画面成本由「对象数」驱动，不由「面数」驱动。**
1307 格 ≈ 2600 个 renderable（侧壁 + 顶面各一个 mesh），每个吃一次 draw call 的固定开销。
现在还能跑，但这是第一个会崩的地方——成熟局面已接近 3000 格的量级，到时直接掉到 30fps 以下。

### 1.2 视觉层面

- **消缝做到了**：`0.998` 的方块 + 顶面 `×1.28`，地面已经是一整块陆地而不是一托盘瓷砖（`650b351`）。
- **但边界没有交代**：地形边缘是直角切面，没有坡、没有碎石、没有高度过渡。岛的外缘像被刀切的蛋糕。
- **水面远看是一块蓝纸**：顶点波幅 0.013，全屏视角下只有 1–2 px 的位移，等于没动。

## 2 美术风格特色

现在是**三种语言打架**，没有人把它们缝起来：

1. **低多边形方块地形**——Minecraft 血统，几何语言。
2. **手绘纸牌立牌**——2D canvas 贴图的 billboard，插画语言。
3. **深蓝海 + 水平线**——写意风景，氛围语言。

三者各自都能自洽，但缺一个统一的手：

| 断点 | 具体 |
|---|---|
| 色板不统一 | 地形是低彩度橄榄绿（草地 0.15 明度），卡面是饱和元素色（木 `#5e8f47`）→ 立牌像贴在灰绿板上的贴纸 |
| 描边语言缺失 | 立牌有手绘边，地形是硬直角，两者不属于同一个世界 |
| 尺度不统一 | 立牌 200×200 px 贴图对应 1.0 世界单位，近景直接糊 |
| 同一套照明 | 立牌、地形、水面亮度接近，无主次 |

### 建议定调：纸片剧场（paper theatre）

把「手绘立牌」当唯一的手工语言，地形降为它的舞台：

- 地形走**两色平涂 + 纸纹叠加**，不再做明暗渐变；
- 立牌加 **1.5px 深色描边**；
- 全场景共用**一张纸纹**（地形、立牌、UI 卡面）。

**为什么选这条**：走写实立体（PBR 地形 + 植被模型）在纯浏览器 + 1300 格规模下必然掉帧，
还要美术产能；纸片剧场只改材质和一张纹理，是唯一「成本可控而风格能立住」的路。

## 3 光影表现

### 3.1 硬数据

- 视口亮度 **mean 0.206**
- 直方图（0.1 一档）：

```
[67810, 156855, 555193, 37306, 208, 0, 0, 0, 0, 0]
   8.3%   19.2%   67.9%   4.6%  0.03%   0     0     0     0     0
```

- **0.2–0.4 占 72.5%**；0.4–0.5 只有 **208 像素（0.03%）**；**0.5 以上全空**。

### 3.2 成因（按贡献排）

1. **没有阴影**。全场只有半球光 + 一盏方向光的漫反射，地面没有任何投影，格与格之间零明暗差。
   `R.jitOf` 做了 ±0.03 的连续起伏——但**没有阴影就没有立体，起伏白做了**。
2. **没有亮部**。地形色全部低明度（草地 `#25452c` ≈ 0.15），乘 Lambert 后更暗。
   天空不进画面统计，反证**地平线在视口外**——画面里根本没有天。
3. **没有分层**。所有元素同一套照明，立牌、地形、水面亮度接近，读不出远近。

### 3.3 修法（都不需要美术资源）

- **(a) 烘焙式明暗**：不用实时光影，在顶点色里直接烘 `dot(法线, 光向)` 的四档阶梯（cel shading）。
  1307 格 × 4 档是静态数据，零运行成本。这一条能直接修掉「0.5 以上 0 像素」。
- **(b) 把天放进画面**：让地平线进视口，或用雾把远处压暗、把天压下来。
- **(c) 加轮廓暗部**：侧壁固定压到顶面的 **0.62** 倍；立牌底部加一道 **0.35** 的接地渐变。
  只这一条就足以让画面「立起来」。

## 4 高清贴图与建模精度

| 项 | 现状 |
|---|---|
| 立牌贴图 | **200×200 px** canvas 绘制，近/中/远共用一张，无 LOD |
| 地形贴图 | 无（纯色 + 顶点色）—— 合理选择，不算缺陷 |
| 建模精度 | 一格 = 一个方块 + 一个顶面平面 + （可选）一个立牌 |
| 树 / 灌木 / 动物 | 全是 billboard，无几何 |
| 几何复用 | **无**。1674 个 geometries > 1307 格 |

**判断：当前精度水平与「纸片剧场」的定调是匹配的，不该去追高清模型。**
该做的是三件小事：

1. 立牌提到 **400×400**，开 `generateMipmaps` + `anisotropy 4`；
2. 立牌按距离切 LOD（近 400 / 中 200 / 远 128）；
3. 地形几何按**高度档**共享——高度只有 5 档，不需要 1307 个不同的 BoxGeometry。

## 5 核心玩法与操作手感

**链路（已实装）**：选牌（点 / 数字键）→ 拖到格 → `castRange` 描边 → 落点扩散环 → 松手
→ `gateCheck` → op 内二次校验 → 施放 + 痕迹环。

**已经够了的部分**：预览有、范围有、落点有反馈、失败有文案、撤销有守卫、重抽有梯价。
机制完整性不缺。

**手感的问题全在「判定分散在两层」**：

- 第一层 `S.playable(card, life)` —— 只看世界（要不要有植物 / 兽），**签名里没有 cell**，因此永远不知道落点；
- 第二层 `S.gateCheck` + 各 op 内部校验 —— 才知道「这一格行不行」。

结果：**手牌亮着 → 拖过去 → 松手 → 被拒**。四次操作换来一句否定，
而这个否定否掉的是**系统刚刚给出的肯定**。这比「没牌可打」伤人得多。

## 6 卡手：具体表现与成因

### 6.1 表现（实测）

**表 1｜一局从头到尾能打几张**

| 时刻 | 手牌 8 张里能打 | 说明 |
|---|---|---|
| 开局（空世界） | **2**（土地、太阳） | 6 张灰 |
| 打完第一张土地 | **8**（全亮） | 灰显立即失效 |
| 中期 | 频繁变化但**从不阻塞** | `refill.dead = 0/400` |

**表 2｜全池的可打面**

- 55 张卡里，**8 张**能在空世界施放（4 张 `land` + 1 张 `sun` + 3 张 `law`）；
- 其余 **47 张（85%）必须落在已有地块上**；
- `op` 分布：`field` 17 + `spawn` 18 = **35 张（64%）** 是最重的一类，全部要求「已有地块」；
  而 `land` 只有 **4 张**。

→ 8 张手牌里 land 的期望是 `4/55 × 8 ≈ 0.58` 张。**平均两次开局就有一次摸不到土地卡，直接卡死。**

**表 3｜谎报（高亮说能打，落下被拒）**

| 卡 | op | 拒因 |
|---|---|---|
| 擦痕 | `wound` | 这一格没有活物 |
| 萌发 | `grow` | 这一格没有植物 |
| 疯长 | `grow` | 这一格没有植物 |
| 引燃 | `ignite` | 这一格没有可燃的植物 |

**表 4｜随机施卡 1200 次**

- 成功 **202**，失败 **36**（其余为无效落点 / 未执行）；
- 36 次失败中 **35 次（97%）** 是「要放在已有地块上」。

### 6.2 成因（按影响排）

1. **判据只有「世界级」，没有「格级」**。`S.playable` 的签名里没有 `cell`，
   结构上就无法回答「这一格能不能打」。这是表 3 那 4 张卡的根本原因。
2. **85% 的卡共用同一个前置「要有地块」，而地块卡只占 4/55**。稀疏度靠运气解决不了。
3. **灰显的粒度选错了**。现在按「世界」灰，正解是只在「整副牌库都推不动了」（真死局）时才灰；
   「这一格不行」属于落点层的信息，不该动手牌。
4. **判据写了两遍**。`playable` 与 `gateCheck` / op 内校验各一套，必然漂移。4 张谎报卡就是漂移的可见部分。

### 6.3 修法

- **P0-2 单点真源**：`S.playable(card, life, cell)`——传 cell 判格，不传判世界。
  手牌重绘时机从「每月一次」改成「hover 换格时」。
- **P0-1 保底发牌**：新包至少 1 张 `land`。现成的位置是 `S.FRESH_PER_PACK` 旁边加一条硬规则。
- **P0-3 落点承担否定**：拖到不可落的格，预览描边转红 + 一句 ≤6 字的拒因（复用已有 msg），
  **手牌不降饱和**。让否定发生在按下去之前。
- **P1-3 前置可视化**：对 35 张 `field`/`spawn`，在卡面右下角加 12px 的「需地块」图标（不是文字）。

## 7 新手门槛与引导缺失

### 7.1 首屏实测

- 屏幕正中**只有两行字**：「世界是空的」「先打一张「土地」」；
- **没有任何「怎么放」的说明**——拖？点？按什么键？
- 手牌 8 张里 6 张灰；
- **最左被默认选中的是「土山」**，不是提示里说的「土地」。

### 7.2 四个门槛（按劝退顺序）

1. **不知道该做什么动作**。不是难度问题，是**没有可观察的示范**。
2. **提示点错对象**。文字说土地，选中态是土山。第一步就撞上「说的和做的不一致」。
3. **灰牌没有解释**。6 张灰牌的 `title` 里其实有原因（「这里还没有植物」），但要悬停才看得到。
4. **世界转起来之后没有目标**。能打牌、能看它长，但「我造这个干什么」——`STATUS` 里没有目标定义。

### 7.3 修法（不加解释性文字）

- **P0-3 首屏即示范**：开局手牌固定前两张是「土地」+「太阳」，并且土地卡**自动处于拖拽态**
  （指针在半空、落点预览已在闪）。用户只需松手。
- **P0-3 选中态对齐**：`W.sel` 初值指向 land，不是 index 0。
- **P1-3 灰牌给原因**：灰牌右下角一个元素色小问号，点一下弹一句已有文案。不加常驻句子。
- **P2-3 目标层**：不做引导，做**可见的进程**——第一棵树、第一只兽、第一座村，用年表的纪年行带出来
  （`S.addChron` 已有）。

## 9 施工顺序

**第一批（逻辑层，不碰渲染）**：P0-1、P0-2、P0-3、P1-3。
四处全在 `sim/cast.js` + `ui/hand.js` + `ui/boot.js`，改完立刻可量化：
开局可打张数 2 → 3+、谎报 4 → 0、首屏有示范动作。
**这是「卡手」唯一该先做的事**——先把否定前移。画面再好看也救不了被拒的手感。

**第二批（渲染层，三条互相咬合）**：P0-4、P1-2、P1-4。
顶点色烘焙的同时把立牌 LOD 和接地渐变一起做，一次拍图就能验。

**第三批（按需）**：P1-1 合批、P2-1 定调。
合批必须等地形几何稳定，否则每次改地形都要重算。定调是产品决策，需要拍板。

---

**最后一句**：现在最贵的不是「不够好看」，是**「不信它」**——卡说能打，它说不行；提示说土地，它选了土山。
修完第一批，用户才会开始在意第二批。
