## §2 汇总人自查：拖到面板上会施卡

我自己压拖拽边界时发现：**画布是整屏铺的，左右两栏与面板都浮在它上面**，
按「指针在画布矩形内」判「在世界里」会把面板背后的格子也算进来。
实测把牌拖到**右栏**上松手：`cells 81 → 94`，牌施在了看不见的格子上。

改成用 `document.elementFromPoint` 判「指针底下到底是什么」。
`#ghost` 是 `pointer-events:none`，不会干扰判定。修完复测：左右栏/顶栏三种边界都不再施卡。

## §4 窄屏与键盘（32 条）

| 视口 | 结论 | 主要症状 |
|---|---|---|
| 1080×700 | 局部坏 | 末卡旋转角压右栏 23px；动作栏第 4 个被末卡盖；键位表只露 8/20 行 |
| 1366×860 | 局部坏 | 末卡压右栏 19px；动作栏 4/4 被盖；键位表 11/20 |
| 1281→1280 | 跳变 | 一个像素内：右栏 292→320、左栏 56→52、手牌 1→.9、牌宽 136→122 |
| 1440×900 | 局部坏 | 末卡压右栏 19px；动作栏被盖 |
| 1680×600 | 局部坏 | 右栏「痕迹」只剩 24px（内容 536px） |
| 900×1200 | **崩** | 手牌 658 进 580 容器：首卡压左栏 35px、末卡压右栏 51px |

**根因两条，都不是「小屏没适配」**：
1. **扇形是转过的**：最外侧卡转 ±8.4°，136×216 旋转后左右各溢出约 16px，而布局按未旋转的矩形算宽度 → 必然压到栏上。
2. **`#actbar` 是 `#handwrap` 的子节点**：它的 `z-index:34` 只在手牌这个层叠上下文里比大小，而卡片最高到 200 → 右下角按钮被最右边那张卡盖住。

键盘侧 14 条，最重的是 **K01/K02**：面板打开后焦点没有进入面板（仍有 24 个背景 Tab 停点），且**空格会穿透到世界放牌**。

## §5 世界画面（35 条，全部带量化）

这一节的方法值得单独说：所有结论都是读数，不是观感。样本世界 13×13=169 格、152 实体、127 立牌，
1 世界单位 ≈ 132px。

| 编号 | 量化结论 | 严重度 |
|---|---|---|
| **W04** | 阴影贴图每帧照跑一遍，但**全场 0 个 castShadow**（地形 `castShadow=false`、立牌是平面）→ 3.81ms/帧、+55% | P1 |
| **W10** | 水域与陆地是 **0.265W 的断崖**（水 h=0.22，陆 h=0.30，无过渡） | P1 |
| **W11** | 每个水格各自起波相 → 相邻水格交界处 **ΔL 31.6/255（12% 亮度断线）** | P1 |
| **W28** | 相机能穿进地形（俯角浅 + 拉近时近裁剪面切进地块内部） | P1 |
| **W21/W22** | 痕迹环在沙地上 **ΔL 0.66/255 ≈ 0.26%**，等于看不见；「这里被写过」的标记失效 | P1 |
| **W32** | 摆件模式不重算取景，主体挤在右下 | P1 |
| **W01** | 108 张草牌只有 3 个轮廓 → 读作盖章（与上轮 U28 结论一致，但这次给了分布） | P2 |

**W04 是这一轮最便宜的一次收益**：关掉一个什么都不做的 pass。

## §6.1 两处「修好了 A、付出了 B」的账

窄屏这一批有两处是**用另一个指标的恶化换来的**，记在这里免得下次当成新 bug 再修一遍：

| 修复 | 换来的代价 | 当前的取舍 |
|---|---|---|
| 手牌两端各让 17px（防末卡压右栏） | 1080 下重叠从 32px 涨到 **37px**，末卡右侧约 31% 被邻卡盖住 | 保留。「压到栏上」是坏的，「盖住正文」是密；名字居中永远露得出来 |
| `#actbar` z 34→300（防被手牌盖） | 1080–1440 下动作栏反过来压住末卡右侧 **13–22px**，正好盖住回收值 | 保留。改之前是「按钮完全点不到」，现在是「一角被盖、按钮能点」 |

> 这两条要真正解决都得改布局（窄屏换手牌排列、动作栏换个位置），不是调数值。
> 调数值只能在这两个坏结果之间挪，挪不出「两个都好」。
