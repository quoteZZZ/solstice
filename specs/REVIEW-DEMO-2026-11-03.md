# 原型评审 2026-11-03

> 评的是**跑起来的那一版**（`prototypes/solstice/index.html`，55 张卡 / 8 个抽屉 / 手牌上限 8），不是规格。
> 结论按七个维度分开写，每个问题一个编号（`T` UI·文字 / `V` 画面 / `C` 组件 / `F` 流程 / `S` 风格 / `X` 缺陷 / `R` 借鉴），
> 改法都指回编号，末尾 §8 给总表与排期。

证据等级：**E1** = 本机实测数字或截图 · **E2** = 代码位置可查 · **E3** = 外部案例推断。

## 1 UI 与文字设计

### 1.1 结论

**排版不是"不够精美"，是"读不了"。** 全站 64 条字号声明里 **37 条 ≤10px（58%）**，而这些小字恰好承载了全部说明性信息：单位、条件、日期、来源。同时这套小字用的是 `--ink3` / `--ink4` 两档灰，对 `#0a0c10` 底色的对比度是 **2.60:1 / 1.77:1**——远低于 WCAG AA 的 4.5:1。**小而暗叠在一起，等于这一层信息不存在。**

文字本身的质量反而不错：卡面 `fx` 长度 16–34 字、均值 25.1 字，短句直给（「本格保水 ×0.6，水不再往下漏；旱季更耐。」），没有浮夸风味文案。问题在**一致性与可读性**，不在文笔。

### 1.2 问题

| # | 问题 | 证据 |
|---|---|---|
| **T-1** | **字号失控**：7 / 7.5 / 8 / 8.5 / 9 / 9.5 / 10 七档并存，无层级规范。7px 出现在卡库网格标签（`.cgCell .cgTag`），8px 出现在空态占位与图鉴底注 | E1：`grep font-size styles/*.css` 统计；E2：`styles/panels.css:43,47,55,62` |
| **T-2** | **对比度不足**：`--ink4 #333d48`=**1.77:1**、`--ink3 #4c5563`=**2.60:1**；图鉴未点亮卡正文 1.82:1、卡库空格 1.41:1 | E1：色值实测计算；E2：`styles/app.css:5`、`panels.css:58,62,47` |
| **T-3** | **手牌文字实际渲染 6px**：卡面按 302px 宽设计、`fx` 12px，手牌缩放后 `fx` 只有 6px、`cond` 4.75px、编号 4.25px | E1：`getComputedStyle` 实测 12px × 手牌缩放；E2：`styles/card.css:73,76,84` |
| **T-4** | **卡面条件句式 7 种并存**：63 条 `cond` 里「需…」36 条、「本格有…」4 条、不等式 9 条，其余散在「由苔进化」「生命层：动物」「夜 18–6」「已有植物」「只能落在虚空」「附近有…」 | E1：运行时统计 55 张卡 |
| **T-5** | **术语混语种**：中文卡面上出现小写 `hp`（2 张卡）；`幅度`（创世/土地）、`环`、`时素`、`池` 均无定义，界面上没有任何一处能查到 | E2：`data/cards.matter.js` 等；截图 01 创世 |
| **T-6** | **单位标签不可读**：顶栏 `格 / 时素 / 种`、底栏 `手 / 池` 用 9px + `--ink4`（1.77:1），在 1280 宽下等于装饰 | E1：截图 02 / vp-1280 |

### 1.3 改法

1. **建三档字阶，砍掉其余**（对应 T-1、T-6）：`11px` 微型标签 / `13px` 正文 / `18px` 数字。全站只允许这三档 + 卡面内部的两档（19px 标题、12px 效果）。落点：`styles/app.css` 的 `:root` 加 `--t-micro/--t-body/--t-num`，把 64 处硬编码逐个替换。**工作量 1 天，收益最大。**
2. **升两级灰**（T-2）：`--ink3 → #6b7887`（4.9:1）、`--ink4 → #56626f`（3.6:1），并把"装饰性"与"可读性"分开——装饰可以暗，凡是**人名、单位、日期、条件**一律不许用 `--ink4`。工作量 0.5 天。
3. **手牌分层出信息**（T-3）：卡在手里只显示 `标题 + 图形 + 一行 8 字以内的摘要`，完整 `fx` 在悬停/选中时才出（现在 `#cardtip` 已有这套，只是手牌里仍画了全文）。把手牌卡改为专用版式 `card.h` 而不是把 302 版整体 `scale(.5)`。工作量 1.5 天。
4. **统一 `cond` 句式**（T-4）：定成两种——`需 X`（前置条件）与 `X ≥ n`（数值门槛），其余改写成这两种。写进 [CARD-SCHEMA.md](CARD-SCHEMA.md) 的「卡面文字」一节，加进 `npm run cards` 的软警告。工作量 0.5 天。
5. **术语表落在一处**（T-5）：`hp → 生命`；`幅度` 改成具体单位（`抬升 1 格`）；`环 / 时素` 的释义放进卡库的筛选列脚注（不是弹窗、不是说明句）。工作量 0.5 天。

## 2 画面设计

### 2.1 结论

**世界画面是这一版最弱的部分，也是它本该最强的地方。** 现在它读起来像**一张铺开的绿桌布上画了格线**：没有地势高差、没有水面、没有影子、没有地平线，每格草是同一张精灵图、同一朝向。而"施卡造世界"这个卖点，全靠这一张画面承载。

### 2.2 问题

| # | 问题 | 证据 |
|---|---|---|
| **V-1** | **地形零高差**：所有格子都在同一平面，陆地与水的区别只是贴图颜色。看起来是"画上去的方格"而不是"长出来的地" | E1：截图 14（全隐） |
| **V-2** | **精灵图完全重复**：每格草是同一张 3 叶草、同一旋转、同一缩放；树是同一张正面三角。行列对齐形成明显摩尔纹 | E1：截图 03 / 14 |
| **V-3** | **痕迹环反客为主**：每施一张卡就在格上留一个同心圆环，25 张卡之后地表被环纹铺满，地形本身被盖住。它现在是**主体纹理**，不是"痕迹" | E1：截图 vp-1280（25 环）；E2：`render/trace.js` |
| **V-4** | **没有地平线与远景**：相机俯角低、视野内全是地面，顶部一条深蓝横带收边。看不出这是个**小岛**，"微缩世界"的体积感消失 | E1：截图 14 |
| **V-5** | **无光照关系**：打了太阳，却没有影子、没有受光面差异；草与树没有接地阴影，像浮在桌面上 | E1：截图 14 |
| **V-6** | **格线权重过高**：全屏等权深色网格压在一切之上，不做遮挡、不随距离淡出。这是棋盘语言，不是世界语言 | E1：截图 14 |

### 2.3 改法

1. **给地形高程**（V-1、V-4）：`land` 卡已经带 `size`，让地块中心抬 `+0.06`、边缘回落，水面下沉 `−0.04`，一张 5×5 的地表立刻有起伏；格子 mesh 从平铺 quad 改成一个带上凸的 4 段片。**这一项做完，V-1/V-4/V-6 会一起改善**。工作量 2 天。
2. **精灵图去重复**（V-2）：每格用 `hash(x,y)` 派生 3 个变体（旋转 ±12°、缩放 0.85–1.15、色相 ±4°），不增加资源，只增加参数。工作量 0.5 天。
3. **痕迹降级为"薄薄一层"**（V-3）：环改成贴着地表的低透明度环形渐隐（alpha ≤0.25），并在 12 个月后淡出（现在只在过期时消失）；同时把"最近 4 条"从右栏文字改为**在地表显示 1 个脉冲点**。工作量 1 天。
4. **加接触阴影**（V-5）：立牌与树在格面投一个 soft circle（贴图即可，不做实时阴影）。工作量 0.5 天。
5. **格线按距离淡出**（V-6）：`R.grid` 的线材质换成按世界坐标距离衰减的 alpha，边缘淡到 0.15。工作量 0.5 天。

> 这五项里 **1 与 2 是同一件事的两半**（让地表有三维信息），合计 2.5 天能从"棋盘"跨到"微缩地形"。

## 3 组件设计

### 3.1 结论

**单个组件的做工不错（卡面、toast、事件卡都成立），但它们之间没有共同的规格**：8 个抽屉各写各的布局，同一个"筛选"在三处有三种形态，同一个"状态"（可改/锁死/冲突）有四种表达。**一致性缺的是"一份组件清单"，不是"更漂亮的设计"。**

### 3.2 问题

| # | 问题 | 证据 |
|---|---|---|
| **C-1** | **面板骨架不统一**：抽卡是「左卡右展示」、卡库是「左筛选 + 中网格 + 右详情」、年表是「左列表 + 右详情」、设置是「左 tab + 右 3 行」、键位是「顶 tab + 长表单」——五套骨架，玩家每次都要重新找"我在哪一层" | E1：截图 05/07/08/09/10 |
| **C-2** | **抽屉过多稀释主线**：左栏 8 个图标（抽卡/卡库/年表/创世/设置/键位/帮助/摆件），全部**无文字标签**（`.rail span{display:none}`），只靠原生 `title` 提示；图标是自制抽象符号 | E2：`ui/hud.js:44`、`styles/app.css:83`；E1：截图 02 左栏 |
| **C-3** | **"筛选"三种形态**：卡库是竖列元素按钮、年表是横排 tag、键位是顶 tab、图鉴又是竖列——同一个动作四种控件 | E1：截图 07/08/10/06 |
| **C-4** | **空态无表达**：卡库选「水」时 24 格只有 1 张卡，其余全写「—」（对比度 1.41:1）；抽卡面板右侧一大片空白里只有一个虚线小方块写「时素不够 · 还要 28」 | E1：截图 07 / 05 |
| **C-5** | **响应式完全缺失**：1280×720 / 1440×900 / 1920×1080 三档，`fx` 恒 12px、手牌卡恒 182px、右栏恒 320px。4K 上 UI 会小到不可读，1280 上手牌 8×182=1456px 会溢出并被右栏压住 | E1：三档实测；E2：`styles/app.css:11` |
| **C-6** | **反馈文案不统一**：toast 有「进入这一界 / 键位冲突 / 时素不够」，还有直接 `UI.log` 的、直接写右栏的，同一件事三种去处 | E2：`ui/hud.js`、`ui/panels.js`、`ui/hand.js` |

### 3.3 改法

1. **定一份面板骨架**（C-1、C-3）：所有抽屉统一为「**标题 + 左侧一个筛选列（单一形态：竖列按钮）+ 主区**」，主区宽度自适应，详情**同屏右侧**（Tab 视图的 460px 是现成的）。工作量 2 天，一次改五个面板。
2. **抽屉从 8 收到 5**（C-2）：保留 `卡库 / 图鉴 / 年表 / 设置 / 帮助`；`抽卡` 上移到顶栏那个已存在的按钮；`键位` 并入 `设置` 的第四栏（那里本来就有 tab）；`创世` 改成顶栏右端的「换界」并加二次确认（见 X-4）；`摆件/全隐` 保留为快捷键 + 左栏底部一个。工作量 1 天。
3. **左栏给文字**（C-2）：竖向图标 + 9px 竖排标签，或 hover 展开成「图标 + 文字」的宽 120px 抽屉。现在这个纯图标 + 原生 tooltip 的组合是最难用的一种。工作量 0.5 天。
4. **空态写清"为什么空"**（C-4）：卡库空格不再画「—」，改成不画；抽卡面板的"时素不够"改为进度条（`当前 2 / 30`）。工作量 0.5 天。
5. **字号与卡宽跟视口走**（C-5）：`html{font-size:clamp(14px,0.9vw,18px)}`，全站字号改 `rem`；手牌卡宽 `clamp(140px,11vw,200px)`。工作量 1 天。
6. **反馈只有一个出口**（C-6）：`UI.toast` 只用于"结果"，`UI.log` 只用于"流水"，二者不许互串；写进 [TECH.md](TECH.md) 的原型约定。工作量 0.5 天。

## 4 游玩流程

### 4.1 结论

**从"打开"到"知道该干什么"之间，隔着一个隐形的台阶；从"想抽一张新卡"到"真的抽到"，隔着一堵数值墙。**

前者是一句话的事（开场提示的对比度），后者是设计级的（抽包 30 时素 ≈ 300 世界月 ≈ 回收 30 张 0 环卡，而手牌上限只有 8）。

### 4.2 问题

| # | 问题 | 证据 |
|---|---|---|
| **F-1** | **开场引导几乎不可见**：「世界是空的 / 先打一张「土地」」是全屏对比度最低的东西之一（`#hint` 11.5px、`opacity` 很低），而它是唯一的新手引导 | E1：截图 02；E2：`styles/app.css:62` |
| **F-2** | **抽卡在数值上不可达**：开局时素 0；每世界月 +0.1（即 1 时素 = 10 月）；抽包 30 → **300 月**。回收是唯一来源：0 环卡 `value=4`，`reclaim=round(4×0.15)=1` → **抽一包 = 回收 30 张卡**，而手牌上限 8 | E1：`S.PACK_COST=30`、`W.essAcc+=0.1`、`value` 按环固定；E2：`sim/cast.js:6,44`、`sim/time.js:36`、`sim/cast.js:62` |
| **F-3** | **"卡是唯一交互"这条支柱，实际动作为 1 个**：拖放。而键盘只剩「空格=随机落点」，连"选哪个格子"都没有，面板一律 Tab 进不去（X-7） | E2：`ui/boot.js:49,87` |
| **F-4** | **施卡没有落点预览**：放下去才知道水光温怎么变、会不会触发同元素升级；升级规则只写在帮助面板里 | E1：截图 03 前后对比；E2：`ui/hand.js` 的 ghost 只画卡影 |
| **F-5** | **节拍断在"无事发生"段**：前 10 分钟几乎全在等（世界自己跑，玩家无牌可打/无时素）；而事件、图鉴点亮、年表都在后台默默发生，没有把玩家拉回来 | E1：截图 03 的 4 条 toast 同时堆叠——**唯一把玩家拉回来的方式就是堆 toast** |
| **F-6** | **年表不可回看**：71 条形如日志，没有年/月分组，没有"跳到那一刻"，也没有任何画面留存 | E1：截图 08 |

### 4.3 改法

1. **把开场那一句做成唯一的高对比元素**（F-1）：`#hint` 提到 18px / `--ink`、加 1px 描边，且**在玩家打出第一张卡后立刻消失**。不新增任何说明句（守 UI 铁律）。工作量 2 小时。
2. **重定抽卡经济**（F-2）：三选一，建议第三个——
   - ① `PACK_COST 30 → 6`（1 分半）；
   - ② 时素改按"施卡"产（打一张得 1），把抽卡接到玩法上；
   - ③ **抽包不卖钱，改成"图鉴点亮 → 解锁指定卡"**：把 [SETTING.md](SETTING.md) 里已写但没实装的「成就解锁卡池」接上，时素只用来重抽/改写。
   ③ 的好处是把 F-5 一起解决（点亮本身就是节奏点）。**工作量 2 天。**
3. **给键盘一条完整路径**（F-3、X-7）：`Tab` 归还给焦点、`WASD/方向键`移动格子游标、`Enter` 施卡到游标格、`1–8` 选卡（已有）。这是让"不用鼠标也能玩完一局"的最小集。工作量 2 天。
4. **落点预览**（F-4）：持卡悬停时，可落格给 0.15 alpha 的高亮，**会触发升级的格给第二层描边**（这是 R-1 里 Dorfromantik 的核心做法）。工作量 1.5 天。
5. **给"无事发生"一个可见的锚**（F-5、F-6）：顶栏季节旁加一个「本月发生 N 件」的脉冲点，点开即是年表当月的 3 条；年表按"年"折叠。工作量 1.5 天。

## 5 整体风格与特色

### 5.1 结论

**气质是对的，辨识度还没立起来。** 现在的视觉语言是"深蓝夜空 + 金色等宽数字 + 暗玻璃面板"——这是 2020 年后独立游戏很常见的一套（清爽、安全、不冒犯），但它**恰好抹掉了 Solstice 最独特的两件事**：

- **"从虚无开始"**：整个开场是一片空海，这是全网罕见的、敢于让玩家看 10 秒空白的开局。现在被一个几乎看不见的提示句浪费了。
- **"卡改变的是物理，不是数值"**：卡面上写的是「本格保水 ×0.6」「光照 −0.1」，这是罕见的**参数化世界**语言。但画面上完全看不出这些参数在动。

### 5.2 亮点（要保住，别在改版里丢掉）

| # | 亮点 | 为什么值得保 |
|---|---|---|
| **S-1** | **卡面语言**：19px 标题 + 一句 `fx` + 条件行 + 三格小数字，密度克制、没有风味溢美 | 这是全项目最成熟的一处设计；R-5 的 Balatro 走的是相反方向（信息暴增），不要跟 |
| **S-2** | **创世的"世界档案"式呈现**：剖面图 + 判据 7/7 + 坐标码 `SOL-F30-QIR8-7JMD` | 有辨识度，且**不用说一句话**就表达了"这一界是唯一的一界" |
| **S-3** | **暗色 + 单一金色强调**：强调色只有 `--acc #e0a33e` 一处 | 克制是优点。改版时守住"**只有一件事是金色的**" |
| **S-4** | **无失败、无成长**：整个界面确实没有血条、没有分数、没有倒计时 | 与 [CHARTER.md](CHARTER.md) 的三条支柱一致，视觉上没有偷偷加回压力 |

### 5.3 问题

| # | 问题 | 证据 |
|---|---|---|

### 5.4 改法

1. **三色契约**（S-5）：元素色只用于「元素标识」；金色只用于「可执行动作」；语义色（红/绿）只用于「冲突/达成」。其余一律灰阶。写进组件规范。工作量 0.5 天。
2. **给场一个视觉形态**（S-6）：右栏的水/光/温加一条**横向带区**（当前值指针 + 宜居区淡色带，Terra Nil 的做法），并在世界画面上用一个开关切"热力图模式"（水/光/温三选一，整片地形按值上色）。这是**把独特性变成可见性**的最高性价比动作。工作量 2 天。
3. **标题字换一个有性格的等宽**（S-7）：`SOLSTICE` 用一款几何等宽（如 JetBrains Mono / IBM Plex Mono），中文标题保持系统栈。工作量 2 小时。

### 10.1 X-7 的解法（与原建议不同）

原建议是"Tab 归还焦点 + WASD 游标 + Enter 施卡"。实测键位表里 `ambient` 写的就是 **P**，
**Tab 从来只是一条暗绑**——删掉它不损失任何已公布的操作。已做：Tab 归还浏览器、
全局 `:focus-visible`、左栏/底栏/手牌槽补 `tabindex` 与 Enter/空格激活、输入框聚焦时不触发全局快捷键。
WASD 游标未做（需要世界侧一套游标状态，属另一件事）。

### 10.2 新发现：X-18 开局软锁

`S.dealHand()` 的三条保底（land / sun / spring）原来顺序硬写 0/1/2 号槽，
**后一条会把前一条刚写进去的卡连同原本就在那个槽里的同类卡一起盖掉**：
手牌里唯一的土地正好坐在 1 号槽时，「太阳」保底就把它吃了 ——
开局拿到一手没有土地、世界里又一格都没有的牌，而土地是唯一能造格的卡，直接软锁。
已改为只替换「不承担任何保底职责」的槽；实测 400 次发牌，land/sun/spring 缺失 0 次。

### 10.3 这一轮改的两处规则（都不是纯样式）

- `S.playable(card)`：判断一张卡此刻能不能打（土地 / 太阳 / 律恒可打，其余要世界有地且门控通过）。
  手牌用不可打降饱和表示。判据与 `S.gateCheck` 同源，**不改任何规则**。
- `S.castRange(card, cell)`：这张卡会动到哪些格（土地是 size×size 方块，field 的邻居光照与湿地标记带到邻格）。
  落点预览的第二层描边用它，规则仍只在 sim 一处。

### 10.4 命名纠正（2026-11-03 用户）

项目**只有英文名 Solstice，没有中文名**。仓库里「至日 ·」这类项目名用法已全部改掉（42 个文件）；
`TIME.md` §7.2 / `SETTING.md` §1.3.1 里的「至日」是**机制词**（月 0 与月 6 的昼夜分界），不是项目名，保留。

### 10.5 抽卡五选一与卡面信息层级（2026-11-03 夜）

**开包不再往手牌里倒。** 原来一包 5 张全收，手牌上限 8 —— 撕一包就把手牌灌满，
「抽到新卡」从一次决策退化成一次倾倒（F-2）。现在撕包只把 5 张摊在桌上，玩家挑一张：
手牌没满直接进，满了换掉当前选中的那张（换下哪张写进日志）。
三步是「封印 → 翻牌 → 挑选」，选完即收摊，剩下的按「不必挑」放弃。
这不是新发明：Balatro 的 booster pack 与 Slay the Spire 的三选一都是「开了再挑」，不是「开了全给」。

**卡面只回答三件事**：这是什么（类 + 环）、能放在哪（`line.cond`）、做了什么（效果句）。

- 类从 9px 图标改成 10px 字徽（物 / 术 / 律）——图标要背，字不用背。
- 落点约束做成一枚角标，盖在画布左下角，**只标例外**：数据里 11 张卡有 8 张写「需已有地块」，
  每张都挂等于没挂；角标只留给虚空 / 湿土 / 夜间 / 有灌木这类少数条件。
- 效果句保持作者原文，关键数值仍加粗；完整数值与进化链留给悬浮与图鉴。

### 10.6 键盘把一局走完（2026-11-03 夜）

上一轮只做到「Tab 能到按钮」，世界本身仍然只能点。现在补上格子游标：

- **WASD / 方向键**移动游标。相机能绕世界转，所以按键方向先投到世界 XZ、
  再吸到最近的 8 个格子方向之一——不论从哪个方位看，W 都是屏幕上的「向里」。
- **Enter** 在游标那一格施卡；鼠标扫过某格时游标就跟过去，两种输入是同一条路。
- 游标出界时镜头跟着平移。安全区按 **真实面板量**（左栏右边 / 右栏左边 / 手牌上边），
  写死百分比会随窗口和 `uiMode` 变化而失效。
- 游标高亮是三层：`cam.hoverBox` 的 1px 线框（鼠标悬停也用它，会自己淡掉）、
  `marks.cursor()` 的一层白色填充（键盘专用，因为键盘没有指针本身作指示）、
  以及原有的落点预览。
  键盘游标**不淡出**——游标是「我现在指着这一格」，人要想两秒，淡掉就等于没有。

`tests/smoke.js` 新增一段：设一张土地 → 按 `d` `d` → 量游标位置与 `keepHover` → `Enter` →
量格数增量。现在 `landed: 16`（5×5 落地，9 格已存在），`errors: []`。

### 10.7 面板只剩一套骨架（2026-11-03 夜）

### 10.11 抽签三条：保底、去重、回收价（2026-11-04）

一轮借鉴扫描之后动的三条，全部只改抽签与派生，不碰卡表、不碰界面。
出处见 `GAME-SCAN.md`（Slay the Spire 的 rarity offset、炉石 2020 的 duplicate protection）。

| 项 | 改前 | 改后 |
|---|---|---|
| 高环出现 | 纯静态权重，高阶包单抽 4.6 %、六张里至少一张 24.7 %，**连续 6 包全空有 11.5 %** | 旱情补偿：连续没出 7 环，高环权重 **+8 %**（上限 3.2 倍），连续 30 次没出则下一包必给 |

| 撤销回收 | 只校验时素，不校验「是不是刚回收的」也不校验手牌上限 | 只认最近一次回收的回执，**一次性**，且校验手牌上限 |

**1.8 包**，基础池从约 18 包缩到 **7 包**——稀有度直接失效。改成每包 2 张的配额制后才回到

**实测（同批种子各 200 次）**

- 单包见到 7 环以上：31 % → **34.5 %**
- 连续 6 包（36 张）一张 7 环都不出：11.5 % → **0 %**（补偿消掉的是尾部，不是均值）
- 抽穿基础池（42 张）：12 包
- 撤销：无回执时拒绝、刚回收时可撤、第二次拒绝；手牌不再能超过上限

所以问题不是内容太少，是**没有「一局什么时候结束」**——这条仍未做。

**仍未做**

- `disturb` / `cooldown_s` 55 组数值仍空着。
- 撕包后关面板：已付费的 6 张会变成不可达（`packStage` 在重开时被重置为 0）。
- 存档、主循环的异常兜底、`sim.species` 引用校验、气候数据接结算：都还没动。
