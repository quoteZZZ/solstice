# Solstice · 世界画面审计（3D 侧）

**审计对象**：`E:/solstice/prototypes/solstice`（three.js 0.160，1680×1000）。
**范围**：地形 / 立牌 / 水面 / 痕迹 / 相机 / 摆件模式。UI 面板不在本文件。
**方法**：Playwright + `chromium.launch({channel:'msedge',headless:true})`，只读 `render/`、`sim/`；所有读数来自 `window.__dbg`（`R.cam`、`R.hOf`、`R.standees`、`S.W`、`renderer.info`）或截图像素统计（自写 PNG 解码）。不改源码。

**样本世界**（探针 1–4 用同一块，便于横向比）：13×13 = 169 格，其中草地 102 / 水 13 / 林地 8 / 裸地 34 / 岩 12；152 个实体；127 个立牌。
**机位基准**：yaw 45°、pitch 30°、dist 8.6（代码默认 `pitch 0.52 / dist 9`，可视高度 944 px，此时 1 世界单位 ≈ 132 px）。
**读数文件**：`world-shots/metrics.json`、`metrics2..7.json`；探针脚本 `world-probe.js`、`world-probe2..7.js`。

> 说明：本文件里所有「px」都是 1680×1000 视口、`deviceScaleFactor:1` 下的屏幕像素；「W」是格距（=1.0 世界单位）。

## 一、立牌

### W01 · 世界 · 立牌 · 108 张草牌只有 3 个轮廓，读作盖章
- **触发场景**：一片草场（样本世界里 108 个草格全部有草），默认机位 yaw45/pitch30/dist8.6。
- **现象**：立牌只有 3 张纹理（叶片 5/3/7 根），其余变化只有整体缩放与明度；轮廓、朝向、根部那道白色高光完全一致。近景一眼是「同一个图章按了 100 次」。
- **量化**：108 张草牌只用到 3 个 texture uuid，用量 **38 / 36 / 34**（单图复用 36:1）；缩放 0.84–1.18（CV 9.8%）、明度 0.697–0.865（±11%）只改大小和明暗，不改轮廓；全场 127 个立牌只有 14 个 texture（含树/灌木/芦苇/动物）。
- **证据**：`world-shots/w-grass-crop.png`、`world-shots/w-grass-near.png`
- **严重度**：P1
- **建议**：按物种再补 4–6 个轮廓变体，并让缩放/明度抖动带上「相位」（例如整簇草的倾斜方向 ±8°）；同一格内多株时按 i 分配不同变体，而不是按格坐标。

### W02 · 世界 · 立牌 · 相邻格的立牌在屏幕上互相压边（56% 的相邻对）
- **触发场景**：同上，默认机位。
- **现象**：立牌高 0.63–1.34 W、且永远朝相机，屏幕矩形大面积相交；一排草看上去是一堵连续的草墙，单株读不出来。
- **量化**：252 对相邻格立牌中 142 对（56.3%）屏幕矩形相交；交叠面积平均占较小者的 24.2%，最大 79.2%。
- **证据**：`world-shots/w-yaw-2.png`、`world-shots/w-grass-near.png`
- **严重度**：P2
- **建议**：给每格立牌的横向偏移加大（现在 `off` 只有 ±0.19+±0.055），或按格做「疏密」——一格最多 1 株草，密铺交给贴地色斑。

### W03 · 世界 · 立牌 · 尺寸不带物种大小，同一屏里近端草比远端树还大
- **触发场景**：13×13 世界，dist 8.6；近端格（z=+6）与远端格（z=−5）同屏。
- **现象**：立牌只有两档尺寸（树 0.9×1.2、其它 0.66×0.74，再乘 0.84–1.18），`species.size`（0–4）完全没有进入 `buildStandees`；草与太阳树一样大。透视又把近端放大 3.6×，于是近端草占掉半屏。
- **量化**：小立牌屏幕高 p5 75.9 px / 中位 121.3 / p95 267.7 / 最大 486 px（近端格）；树 135.6–247.9 px。近端草是远端草（135.6 px）的 **3.6×**、比最小的树高 258%。物种 `size` 字段取值 0–4，实际只用了 2 档宽度。
- **证据**：`world-shots/w-yaw-2.png`、`world-shots/w-zoom-min.png`
- **严重度**：P2
- **建议**：`w/h` 乘 `(0.8 + e.size*0.12)`，并给近端格做一次距离钳制（近端 > 300px 时压到 0.7×）。

### W04 · 世界 · 立牌 · 全场景没有一个投影体，阴影通道每帧空跑 3.8 ms
- **触发场景**：任意画面。
- **现象**：`moon.castShadow = true`、1024² shadow map 每帧渲染，但 `buildStandees` 从没设 `castShadow`，地块也显式 `m.castShadow = false`。注释写「立牌仍然投影（那道影子是它站在地上的唯一依据）」，代码里没有这一行。于是「站在地上」只剩贴图里烘死的一块椭圆。
- **量化**：`R.scene` 里 `castShadow=true` 的 Mesh = **0**（`receiveShadow=true` 的有 183 个）；`R.frame()` 20 帧均值：开阴影 **10.78 ms**，关阴影 **6.97 ms** → 每帧白烧 **3.81 ms（+55%）**，换来的投影体是 0 个。
- **证据**：`world-shots/w-base-black-crop.png`（立牌脚下没有任何投影方向，只有一块黑饼）、`metrics.json → inventory.casters`
- **严重度**：P1
- **建议**：要么给立牌 `castShadow=true`（只给正面，背面壳跳过），要么关掉 `shadowMap` 与 `moon.castShadow`；不要两者都不做。

### W05 · 世界 · 立牌 · 接地阴影被 alphaTest 裁成硬边黑饼，近景像地上挖了个洞
- **触发场景**：近景（dist 3–5）看草/树根。
- **现象**：贴图里的接地阴影是径向渐变（峰值 alpha 0.42 → 0.26 → 0），但材质 `alphaTest = 0.34`，只允许 ≥0.34 的像素存在，于是渐变只剩中心那一圈 0.34–0.42，边缘是硬切；再乘 `color 0.78`，画面上是一个边缘笔直的黑色多边形。
- **量化**：渐变峰值 0.42、裁切阈值 0.34 → 可见区间只有 0.34–0.42（渐变宽度的 24%），边缘对比 = 0.34 的黑直接压到草地上（草地亮度 ~95/255 → 落地处 ~35/255，ΔL ≈ 60，0 px 过渡）。127 个立牌全部如此。
- **证据**：`world-shots/w-base-black-crop.png`、`world-shots/w-standee-contact-crop.png`
- **严重度**：P1
- **建议**：`STANDEE_AT` 降到 0.12 让渐变完整显示，或把阴影单独画到一个 `depthWrite:false` 的地贴层（不带 alphaTest）。

### W06 · 世界 · 立牌 · 背面壳在斜视时漏出 15–20 px 硬黑描边，并占掉一半 draw call
- **触发场景**：任意斜视（yaw 不等于立牌法线时都能看到）。
- **现象**：每个立牌是两张 plane：正面 + 背后 1.075×1.045、z −0.006、颜色 `0x0a0f14` 的「背面壳」。本意是描边，实际在斜视时从侧面漏出一条纯黑边，草叶像黑色贴纸。
- **量化**：描边宽度 = (1.075−1)/2 × w = 3.75% 牌宽；近景（一格 593 px）草 14.7 px、树 20.1 px；默认机位（一格 132 px）仍有 3.3–4.5 px。draw call：254 张立牌 plane / 472 个 mesh = **53.8%**，其中 127 张是背面壳。
- **证据**：`world-shots/w-grass-crop.png`、`world-shots/w-base-black-crop.png`
- **严重度**：P2
- **建议**：描边改画进贴图（现在贴图里其实已经有一道 `edge` 描边），删掉背面壳；真要保留，偏移收到 0.002 并把颜色改成同色系压暗，而不是近黑。

### W07 · 世界 · 立牌 · F4（83°）把立牌压成地贴，只剩 12% 高度
- **触发场景**：按 F4 / 把镜头拉到俯视档。
- **现象**：`faceCam` 的 `tilt = lean² × 1.45`，pitch 1.45 时 tilt = 1.45 rad（83°），牌面与地面夹角只剩 7°；整张牌平铺在格子上，树看起来是「地上的绿箭头」，草只剩刀尖。
- **量化**：抬升高度 = h·sin(7°) = 1.2 × 0.122 = **0.145 W**（原高 1.2 W 的 **12%**）；屏幕立牌高/格深从 F2 的 1.88 掉到 0.35–1.04（yaw 225° 最低 0.35）；牌长 1.2 W 的水平投影 1.19 W > 格距 1.0（**越到邻格 19%**）。
- **证据**：`world-shots/w-pitch-F4.png`、`world-shots/w-f4-standee-flat-crop.png`
- **严重度**：P2
- **建议**：tilt 上限收到 0.55 rad（≈31°），F4 单独改用「顶视图例」（缩小立牌 + 只留顶面符号），不要让纸片躺平。

### W08 · 世界 · 立牌 · F1（15°）时立牌彻底遮住地面，轴对齐方位格宽只剩 34%
- **触发场景**：F1 低俯角，尤其 yaw 0/90/180/270。
- **现象**：低俯角下立牌仍竖直，格子的「进深」被压扁，一棵草就能盖住身后两三格；轴对齐方位时格子被压成细长条，草地读成一道墙。
- **量化**：yaw 90°/pitch 15°：格投影 160.7 × 41.8 px（宽只有 45° 方位的 34%），立牌 290.2 px = **格进深的 6.94 倍**；yaw 0°/15°：41.8 × 160.7。全矩阵 `standeeVsCell` 在 F1 为 1.50–6.94。
- **证据**：`world-shots/w-yaw0-F1.png`、`world-shots/w-pitch-F1.png`
- **严重度**：P2
- **建议**：F1 档与 F2 合并（最低 25°），或在 pitch < 0.35 时按 `sin(pitch)` 降低立牌不透明度/高度。

### W09 · 世界 · 立牌 · 水格上的立牌根部没入水面 5.6 cm，接地阴影整块消失
- **触发场景**：在已变成水（watersource）的格子上长草/芦苇（施卡或生态蔓延都会发生）。
- **现象**：立牌 base = `hOf − 0.02` = 0.06，而水面顶在 0.08 + 0.036（WAVE_Y）= 0.116；根部与烘死的接地阴影全在水下，看上去是「草从水皮里直接长出来」。
- **量化**：base 0.060 < 水面 0.116 → 淹没 **0.056 W**（占草高 0.74 W 的 7.6%）；该格接地阴影完全不可见。
- **证据**：`world-shots/w-t4-three.png`（草长在水格上，无根部阴影）
- **严重度**：P2
- **建议**：立牌 base 改为 `max(hOf, waterTop) − 0.02`，水格上加一圈水面波纹环替代接地阴影。

## 二、水面

### W10 · 世界 · 水面 · 水陆交界是 0.265 W 的 90° 断崖，全场景 0 个斜面
- **触发场景**：任何带水的世界（水卡、潮湿判地、湖泊）。
- **现象**：水里没有坡。地形全部是轴对齐 `BoxGeometry`，高度差直接表现为竖墙；水面比草地低 0.265 W，从低角度就是一条黑色水渠。
- **量化**：landTop 0.345 / waterTop 0.080 → 落差 **0.265 W**（默认机位 **35 px** 竖墙）；`R.scene` 几何类型统计：Box 49 / Plane 4 / Sphere 2 / Ring 9 / Buffer 31，**斜面/楔形 = 0**。
- **证据**：`world-shots/w-water-wall.png`、`world-shots/w-water-edge-low.png`
- **严重度**：P1
- **建议**：给水陆之间加一圈「岸」：要么把水格的邻格顶面做一个 45° 倒角（可用 Box 的 scale/rotation 或单独楔形），要么把水面抬到 0.22 并降低水格侧壁对比。

### W11 · 世界 · 水面 · 相邻水格之间的波相被重置，每条格缝最大 8 px 高差
- **触发场景**：任何 2 格以上的水面（本例 13 格连成一条水带）。
- **现象**：波纹位移用的是**每格局部坐标** `position.x/position.y`，格子与格子之间相位突变；加上每格顶面是独立 plane（0.998）与独立的 1 px 界缘线，水带被切成 13 块，缝是硬的。
- **量化**：解析：公共边最大高差 `|wave(+0.499,y)−wave(−0.499,y)| = 0.0608 W`，默认机位 **8.0 px**；像素：沿水带竖扫，每条格缝处 1 px 内亮度阶跃 **最大 31.6 / 255**，7 条缝全部命中。
- **证据**：`world-shots/w-water-wall.png`（水面上 7 条等距亮线）、`world-shots/w-water-scan.png`
- **严重度**：P1
- **建议**：波函数用世界坐标（传一个 `uOrigin` uniform），或整片水合成一张 plane；顶面尺寸改成 1.0 消除 0.002 缝。

### W12 · 世界 · 水面 · 每个水格各自算一次底色，水面是 13 块深浅不同的蓝
- **触发场景**：水带 / 湖面。
- **现象**：水格也走 `spot`（sheen × lowFreq × hash），相邻格有可见的整块色差；俯视时像马赛克。
- **量化**：13 个水格中心亮度 90.6 / 90.7 / 90.6 / 92.4 / 92.5 / 93.3 / 95.0 / 108.9；相邻格最大差 **13.9 / 255（15%）**。
- **证据**：`world-shots/w-water-scan.png`、`world-shots/w-water-patchwork.png`
- **严重度**：P2
- **建议**：水面的 `spot` 用低频连续函数（波长 ≥ 8 格），不要带 hash 项。

### W13 · 世界 · 水面 · 水面无任何反射，只有一层平高光
- **触发场景**：任意水面。
- **现象**：`MeshStandardMaterial({roughness:0.16, metalness:0.34})`，但 `envMap = null`、`scene.environment = null`、无 normalMap、无反射探针；金属度没有环境可反射，只剩下方向光/点光的高光，而波形只位移顶点不改法线，所以高光也是一片平的。画面上看不到树、天、岛的任何倒影。
- **量化**：`envMap:false`、`normalMap:null`；场景内 CubeCamera/Reflector 数量 0。水面区域（300×220 px）平均亮度 98.8、sd 8.9，整片落在 90–110；天空色 #1c3d4b 的亮度是 55，树影 <60 —— 水里**没有任何**对应像素，即没有倒影、也没有树影。
- **证据**：`world-shots/w-water-default-crop.png`、`world-shots/w-water-near.png`
- **严重度**：P2
- **建议**：退一步至少加一张环境贴图（PMREM 一张天空渐变，成本极低），或把 `envMapIntensity` 接到天空球；进阶再加一层屏幕空间反射。

### W14 · 世界 · 水面 · 默认机位下波幅只有 4.6 px，水是静止的蓝色塑料
- **触发场景**：默认 dist 8.6 的常规游玩。
- **现象**：波幅 0.024+0.011 = 0.035 W，只靠顶点位移，且被格缝切断；远看完全没有「水在动」的信号。
- **量化**：默认机位 0.035 W × 132 px/W = **4.6 px** 峰峰值，除以单格 132 px 只有 3.5%；dist 3 时才有 0.035 × 376 = 13 px。无 UV 流动、无法线动画、无高光扫过。
- **证据**：`world-shots/w-water-default-crop.png`
- **严重度**：P2
- **建议**：加一层 UV 流动的细节贴图（或法线滚动），把「在动」交给高频而不是低频位移。

### W15 · 世界 · 水面 · 水格是「透明盒子 + 独立顶面」，一格 3 个 draw call、两层透明叠加
- **触发场景**：任意水。
- **现象**：水格既要画 0.82 透明的 box，又要画 0.86 透明的顶面，还要画 1 px 界缘线；相邻格的侧壁在水下互相透视，边界处颜色叠加不一致。
- **量化**：13 个水格 = 13 个 box + 13 个顶面 + 13 条界缘线（逐格生成）；169 格世界 draw call 562 → **3.3 call/格**，水格是陆格的 3 倍；水体是两层透明叠加（0.82 × 0.86）。
- **证据**：`metrics.json → inventory.drawCalls / waterMeshes`
- **严重度**：P3
- **建议**：水格只保留顶面 + 一圈连续的岸壁；水体用一张整片 mesh 或至少合并同材质的相邻格。

## 三、地块与边界

### W16 · 世界 · 地块 · 格与格的分界靠「每格底色差」，没有线、没有缝、没有影
- **触发场景**：隐去立牌、只看地面（F4 最能看清顶面）。
- **现象**：格距 1.0、方块 0.998，缝只有 0.002（默认机位 0.26 px，看不见）；界缘线只在「地形变化/岛缘」画。剩下能分辨格子的只有 `spot` 造成的整格色差，画面读起来是「拼色地砖」而不是连续地形。
- **量化**：F4 扫描线上相邻格亮度阶跃 **8–43 / 255**（同一块草地上）；0.002 缝在默认机位 = 0.26 px、F4 = 0.36 px；内部格面 676 个，界缘线段只有 184 段（27%）。
- **证据**：`world-shots/w-ground-only-F4.png`、`world-shots/w-grid-F4.png`
- **严重度**：P2
- **建议**：把 `spot` 的低频项降权到 ±4%，改用一条真正的连续格线（或 0.01 的凹缝 + 侧壁压暗）来表达格网，避免「色块拼贴」。

### W17 · 世界 · 地块 · 界缘线只有 1 px、16% 不透明，合成后 ΔL ≈ +7
- **触发场景**：地形交界、岛缘。
- **现象**：设计上「界缘必须有交代」，实际是一条 1 px 的冷白线，压到 0.16 后几乎融进地表；在草地上只比底色亮一点。
- **量化**：线色 #8fb8c8（亮度 176）、草地亮度 ~95，0.16 alpha 合成 → 108（**ΔL +13**），1 px 线经抗锯齿实际覆盖 ~0.5 → **+6.5**；线段总数 184（27% 的格面）。
- **证据**：`world-shots/w-ground-only-F2.png`、`world-shots/w-water-wall.png`
- **严重度**：P3
- **建议**：界缘线改成 2 px 的「外亮内暗」双线，或干脆用侧壁顶点色差分（现在侧面 0.50–0.90，差距不够）。

### W18 · 世界 · 地块 · 没有投影，厚度只靠侧面顶点色的 0.50–0.90
- **触发场景**：任何岛缘 / 高差。
- **现象**：方块不投影、也不接收任何真实阴影（casters=0）；立体感全靠 `bakeShade` 给侧面烘的四档明暗。岛缘投不到虚空水面上，地块像贴纸。
- **量化**：castShadow 的 Mesh 0 个；侧面顶点色 0.50–0.90（顶面 1.00、底面 0.34）；岛缘 0.30–0.62 W 的侧壁落在虚空水面上**没有**影子（水面区域亮度 sd 8.9、均值 98.8）。
- **证据**：`world-shots/w-island-rim-crop.png`
- **严重度**：P2
- **建议**：至少给「岛缘一圈」单独做一个投影贴片（比全场景开阴影便宜得多），或者把方向光接收打开、让立牌投一次。

### W19 · 世界 · 地块 · 草原 vs 岩坡能分辨，草原 vs 林地只差 0.08 W 和一块色
- **触发场景**：不同地形相邻。
- **现象**：五种地形的设计原则是「明度齐平、靠色相区分」，但草地和森林的色相也很近；能分出林地主要靠「林地格更暗 + 有树立牌」。
- **量化**：高度 land 0.30 / grass 0.36 / forest 0.44 / rock 0.62 / water 0.08（Δh：草→林 0.08 W = 10.6 px，草→岩 0.26 W = 34 px）；底色 #4a6d42 与 #33523a 的 sRGB 亮度 98.5 / 73.7（ΔL 25，渲染后再被 spot 与光照压缩），草→林之间除了 1 px 界缘线没有别的高差提示。
- **证据**：`world-shots/w-ground-only-F2.png`、`world-shots/w-yaw-2.png`
- **严重度**：P3
- **建议**：林地抬到 0.50 并在林缘加一圈暗边，让「林」有体积感（现在林地的暗色块更像脏了）。

### W20 · 世界 · 地块 · 岛底与虚空水面之间有 0.62 W 的空隙，没有任何交接交代
- **触发场景**：低角度看岛缘（pitch ≈ 10–18°）。
- **现象**：方块底在 y=0，虚空水面在 y=−0.62；中间是空的，低角度看是一段暗带，岛像悬空贴纸。设计要求「边缘的雾不是装饰」，但这里只有一条硬截止。
- **量化**：min cell top 0.08、方块底 0.00、虚空水面 −0.62 → **0.62 W 空隙（默认机位 82 px）**；虚空平面 260×260、opacity 0.9、roughness 0.22、metalness 0.4、**无 envMap / 无波纹**。
- **证据**：`world-shots/w-island-rim-crop.png`
- **严重度**：P3
- **建议**：把虚空水面抬到 −0.05，或给岛底加一圈「倒影/接触暗部」，二者选一。

## 四、痕迹 / 落点预览 / 扩散环

### W21 · 世界 · 痕迹 · 痕迹环与它所在的地形同色系，亮度改变不超过 0.7/255
- **触发场景**：任何施卡之后（这是每次施卡的唯一「成功反馈」）。
- **现象**：痕迹环颜色 = `elColor(card.primary)`，而地形底色也由同一套元素色推出来（草=木、水=水、岩=土）。同元素打到同元素地形上，环和地几乎一个颜色；环又只有 0.16 不透明度、4% 格宽的环带。
- **量化**：四个对照（同机位、一格 593 px、环半径 0.158–0.164 → 94–97 px）：
  木环落草地：整格平均 ΔL **0.66/255**，只有 **5.1%** 的格面像素 ΔL>6（最大 19.7）；
  木环落裸地：平均 0.56，5.1% >6；
  水环落水格：平均 **0.04**，**0.1%** >6；
  土环落岩格：平均 0.27，**0%** >6（最大 6.0）。
- **证据**：`world-shots/w-c-wood-on-grass-trace.png`、`world-shots/w-c-water-on-water-trace.png`、`world-shots/w-t4-on-grass-crop.png`
- **严重度**：P1
- **建议**：痕迹不用元素色，改成一个与地形无关的「墨色 + 元素色描边」；opacity 提到 0.3–0.35，或改成贴地的刻痕（明暗双线）而不是纯色环。

### W22 · 世界 · 痕迹 · 水格上的痕迹被水面整个盖住
- **触发场景**：任何水格上的施卡（水卡、雨、芦苇生长…）。
- **现象**：痕迹高度 = `hOf(cell)+0.012` = 0.092，水面顶在 0.116，环画在水面以下，完全看不到。玩家在水上施卡不会有任何落点反馈。
- **量化**：0.092 < 0.116 → 埋深 **0.024 W**；实测 ΔL **0.04/255**、0.1% 像素 >6（等于不可见）。
- **证据**：`world-shots/w-c-water-on-water-trace.png`（水格上没有任何环）
- **严重度**：P1
- **建议**：痕迹 base 用 `max(hOf+0.012, waterTop+0.004)`。

### W23 · 世界 · 痕迹 · 同一格叠三种元素的痕迹，三个环同心、半径最多差 3.2 px
- **触发场景**：同一格先后打不同元素的卡（很常见：土地→草→浇水）。
- **现象**：环半径只由 `count` 与 `tier` 决定（0.14 + min(4,count)×0.018 + tier×0.006），三色环同心、半径几乎相同，叠起来是一圈发灰的环，颜色互相抵消——截图里只能数出**一个**环。
- **量化**：同格三元素（木 count2/tier1 → 0.182；水 t0 → 0.158；土 t0 → 0.158）两个环**完全同半径**，最大的也只差 0.024 W；默认机位 132 px/W → 相邻两环相差 **0–3.2 px**。三层叠加 alpha = 1−(1−0.16)³ = **0.407**，但三种颜色混成灰白（截图中三色不可分）。
- **证据**：`world-shots/w-stack3-clean.png`（一格三元素，只读出一圈灰环）、`world-shots/w-ring-B-trio.png`
- **严重度**：P2
- **建议**：不同元素用不同角度的扇形/不同半径档（每元素固定 +0.02），或干脆只显示「最近一次」的痕迹。

### W24 · 世界 · 痕迹 · 痕迹只记得 2 个月，长局地表没有任何历史
- **触发场景**：正常推进 4 年（48 tick）。
- **现象**：痕迹寿命表 `[1,2,3,6,12,18,24,36,48,999,999]`，低环卡（1–3 环）只有 1–3 个月；上限 160 条。四年后 `W.traces = 0`，地表只剩下草和立牌——画面不承载「这里发生过什么」。
- **量化**：tier1 寿命 **2 个月**；48 个月后 traces **0**（探针 1 实测），而年表里同期有 20+ 条干涉记录；痕迹数量上限 160。
- **证据**：`world-shots/w-long-after.png`（4 年 2 月，无一圈痕迹）
- **严重度**：P2
- **建议**：给「已发生」保留一层永久底痕（很淡的地表色偏 + 低透明度环），把「正在发生」交给短寿命环。

### W25 · 世界 · 标记 · 扩散环与痕迹环同形同色，尺寸差 6.1×、透明度差 5.75×
- **触发场景**：施卡后的 780 ms 内。
- **现象**：两者都是 `RingGeometry`、都用 `elColor(card.primary)`；扩散环在 780 ms 内从半径 0.19 扩到 1.115（2.2 格直径），峰值 alpha 0.92，正好压在只有 0.16 alpha、0.18 半径的痕迹环上。扩散环亮起时，痕迹环被完全盖掉（截图里只剩大环）。
- **量化**：扩散环 outer 0.5 × scale(0.38→2.23) = **0.19→1.115 W**（痕迹环 0.158–0.212）；峰值 opacity **0.92** vs 0.16（5.75×）；寿命 780 ms；池 8 个。实测 0.44 s 时仍 0.179 alpha、1.42× 缩放。
- **证据**：`world-shots/w-ring-B-trio.png`（大环清晰、三色小环几乎消失）、`world-shots/w-trace-preview-pulse.png`
- **严重度**：P2
- **建议**：扩散环改成「向外扩散的细线 + 快速消隐」，或固定用白色而非元素色；峰值 alpha 收到 0.45，半径收到 0.6 W。

### W26 · 世界 · 落点预览 · 水格上完全看不见（画在水面以下）
- **触发场景**：选中卡片、鼠标悬停在水格上（水卡/湿地相关卡的主要用法）。
- **现象**：预览用 `hv()` → 有格时 `R.hOf(cell)+0.012` = 0.092，与痕迹同理被水面（0.116）盖住；水格上的落点预览是 0。
- **量化**：实测预览前后整格平均 ΔL **0.9/255**，只有 **2%** 的格面像素变化（陆地上同参数是 ΔL 30–39、98–99% 像素变化）。
- **证据**：`world-shots/w-c-water-on-water-preview.png`（水格没有任何覆盖层）
- **严重度**：P1
- **建议**：预览高度改成 `max(hv, waterTop+0.006)`，水格上用「亮边 + 水面涟漪」而不是填色。

### W27 · 世界 · 落点预览 · 预览与键盘游标是两个几乎相同的白/黄方格
- **触发场景**：选中卡片 + 悬停（预览）+ 键盘游标同时存在，或拖拽时。
- **现象**：预览是 0.98² 的琥珀色平面（0.17），游标是 1.02² 的白色平面（0.20）：尺寸差 4%、透明度差 0.03，形状都是「整格填色、无描边」。在裸地上两者只是一块偏黄、一块偏白，读不出「一个是范围、一个是指针」。
- **量化**：0.98 vs 1.02（+4.1%）、0.17 vs 0.20（+0.03）、色相 0xe0a33e vs 0xf4f9ff；两者都是整格填色、无描边、无角标。合成到裸地上的亮度：预览/游标叠加层一起量得 ΔL +36（分离不开，因为它们几乎同尺寸同透明度——这正是问题）。
- **证据**：`world-shots/w-rings-default-zoom.png`、`world-shots/w-ring-B-trio.png`
- **严重度**：P2
- **建议**：预览改成「格框 + 半透明填充」，游标只留一个十字/角标；两者不要都用整格填色。

## 八、上一轮被判定为误读的两条，我是否同意

### U28「立牌重复」——**不同意原判（这条不是误读）**

- **成立的部分**：同一屏里的草牌确实只有 3 个轮廓（108 张 → 38/36/34），缩放与明度抖动只改大小明暗；实测 252 对相邻立牌里 142 对在屏幕上相交（56%），平均重叠 24%、最大 79%——这正是「盖章感」的来源，不是错觉。
- **需要修正的部分**：说「同一张图铺满全场」不准确。实际是 3 张图各占 1/3，且 ±11% 明度、0.84–1.18 缩放在中远景确实起了一点作用；近景（一格 ≥ 300 px）才明显读得出克隆。
- **结论**：现象成立、描述需要收窄；把它整体判为「误读」会掩盖真正的问题（3 个轮廓 + 尺寸不带物种大小 + 硬黑描边）。

### U31「圆环撞车」——**一半同意**

- **不同意的部分**：三种标记的形状其实不一样——痕迹环 0.158–0.212 W、扩散环 0.19→1.115 W、预览/游标是 0.98–1.02 的**方格**。所以「三个圆环撞在一起」这个说法确实不成立，判为误读有依据。
- **同意的部分（真正撞车的是两对，不是一组）**：
  1. **痕迹环 vs 扩散环**：同为 RingGeometry、同为元素色，尺寸差 6.1×、峰值透明度差 5.75×（0.92 vs 0.16），780 ms 内扩散环把痕迹环完全盖住（`w-ring-B-trio.png` 里只剩大环）。
  2. **预览方格 vs 键盘游标方格**：0.98²/0.17 vs 1.02²/0.20，尺寸差 4%、透明度差 0.03，都无描边，只靠色相区分。
- **而且要补一条更严重的事实**：这四样标记在默认机位**都低于可辨阈值**——水格上痕迹 ΔL 0.04、预览 ΔL 0.9；草地痕迹只有 5.1% 的像素 ΔL>6。所以问题不是「撞车」，而是「全都看不见，偶尔撞车」。
- **结论**：不同意「三者撞车」的字面判据；但不同意把它判为完全误读——真实缺陷是「两对同形标记 + 全局对比度不足」，这一条应当保留并改写。
